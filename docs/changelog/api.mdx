Polar uses date-based API versions to evolve the API without unexpectedly changing
the contract your integration depends on. Versions use the `YYYY-MM` format, such
as `2026-10`, and apply to API requests, responses, webhook payloads, and SDK types. [Read more](/api-reference/current/versioning)

**This will become the Current version on October 1st.**

</Update>

<Update label="2026-04">

### Standard Webhooks signing

New webhook endpoints with secrets generated by Polar on or after **September 8,
2026 at 00:00 UTC** use signing compliant with the Standard Webhooks specification.

Endpoints with secrets generated before this cutoff continue to use Polar's
previous signing approach, preserving compatibility with existing integrations.
Endpoints with user-provided secrets also retain the previous approach.
We will continue to support this approach for as long as necessary; there is no
required migration deadline.

To adopt Standard Webhooks signing for an existing endpoint, **regenerate its
secret** and update your webhook handler to use the new secret. When using a
Standard Webhooks library directly, pass the new secret as-is, without
Base64-encoding it first.

See [webhook signature validation](/integrate/webhooks/delivery#custom-validation)
for details on both signing approaches.

</Update>
