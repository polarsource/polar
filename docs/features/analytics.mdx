**Metrics** are the numbers on **Analytics → Metrics**: revenue, orders, subscriptions, checkouts, cancellations, unit economics, costs, usage and seats. Each metric has a name in the dashboard and a slug you request through the API, the CLI or your agent. The tables below list both.

The code examples use API version `2026-10` and the sandbox.

## How metrics are bucketed

You pick a date range and an **interval**: hourly, daily, weekly, monthly or yearly. Polar splits the range into intervals and computes every metric per interval. Each interval is one point on a chart and one entry in `periods` in the API response. The API also returns a `totals` value per metric for the whole range.

Amounts are in cents. Percentages are returned as fractions, so `0.25` is 25%.

## Read metrics

<Tabs>
  <Tab title="Dashboard">
    - Open **Analytics → Metrics**
    - Pick a date range and an interval
    - Filter by product, or leave the filter empty for all products
    - Scroll to a group, such as **Revenue** or **Seats**, to see its charts
  </Tab>
  <Tab title="CLI">
    ```bash
    polar metrics get --start-date 2026-10-01 --end-date 2026-10-31 \
      --interval day --metrics monthly_recurring_revenue --metrics churn_rate
    ```

    See [`polar metrics`](/integrate/cli/reference/metrics).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    What were my MRR and churn rate in October 2026, per day, in my Polar sandbox?
    ```

    Uses the `metrics_get` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

In code, pass the slugs you need in `metrics` to compute only those. Without it, every metric is returned. Filter with `product_id`, `customer_id` or `billing_type` (`one_time` or `recurring`), and set `timezone` for the interval boundaries (UTC by default).

<CodeGroup>
```typescript TypeScript
const result = await polar.metrics.get({
  start_date: "2026-10-01",
  end_date: "2026-10-31",
  interval: "day",
  metrics: ["monthly_recurring_revenue", "churn_rate"],
});

console.log(result.totals.monthly_recurring_revenue);
```

```python Python
result = polar.metrics.get(
    start_date="2026-10-01",
    end_date="2026-10-31",
    interval="day",
    metrics=["monthly_recurring_revenue", "churn_rate"],
)

print(result.totals.monthly_recurring_revenue)
```

```bash cURL
curl -G https://sandbox-api.polar.sh/v1/metrics/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  --data-urlencode "start_date=2026-10-01" \
  --data-urlencode "end_date=2026-10-31" \
  --data-urlencode "interval=day" \
  --data-urlencode "metrics=monthly_recurring_revenue" \
  --data-urlencode "metrics=churn_rate"
```
</CodeGroup>

Each interval has a maximum date range. Check it with `polar metrics limits` (`metrics_limits`, or `GET /v1/metrics/limits`).

## Custom dashboards and export

- On **Analytics → Metrics**, click **Create Dashboard** to group any metrics into your own dashboard
- Use **Export** to download the metrics as CSV
- On the **Overview** page, click **Customize** to choose the metrics shown there

<Note>
  Dashboard only.
</Note>

The names in the tables below are the chart titles. The metric picker shortens a few, such as **Committed MRR**, **Checkouts Conversion** and **Canceled - Too Expensive**.

## Revenue

| Name | Slug | Definition |
| --- | --- | --- |
| Revenue | `revenue` | Gross revenue from every paid order in the interval: one-time purchases, new subscriptions and renewals. Order subtotal, before Polar fees and tax |
| Net Revenue | `net_revenue` | Revenue after Polar's fee and the payment processor's fee |
| Cumulative Revenue | `cumulative_revenue` | Running total of revenue from the start of the range |
| Net Cumulative Revenue | `net_cumulative_revenue` | Running total of net revenue from the start of the range |
| Average Order Value | `average_order_value` | Revenue divided by the number of orders |
| Net Average Order Value | `net_average_order_value` | Net revenue divided by the number of orders |

## Orders

| Name | Slug | Definition |
| --- | --- | --- |
| Orders | `orders` | Paid orders in the interval, whatever the billing reason |
| One-Time Products | `one_time_products` | Paid orders for one-time products |
| One-Time Products Revenue | `one_time_products_revenue` | Gross revenue from one-time product orders |
| One-Time Products Net Revenue | `one_time_products_net_revenue` | Net revenue from one-time product orders |

## Subscriptions

| Name | Slug | Definition |
| --- | --- | --- |
| New Subscriptions | `new_subscriptions` | Subscriptions whose first paid order falls in the interval |
| New Subscriptions Revenue | `new_subscriptions_revenue` | Gross revenue from the first order of new subscriptions |
| New Subscriptions Net Revenue | `new_subscriptions_net_revenue` | Net revenue from the first order of new subscriptions |
| Renewed Subscriptions | `renewed_subscriptions` | Orders with billing reason `subscription_cycle` |
| Renewed Subscriptions Revenue | `renewed_subscriptions_revenue` | Gross revenue from renewal orders |
| Renewed Subscriptions Net Revenue | `renewed_subscriptions_net_revenue` | Net revenue from renewal orders |
| Active Subscriptions | `active_subscriptions` | Subscriptions that have started and not yet ended. Includes subscriptions canceled at period end, paused and past due |
| Committed Subscriptions | `committed_subscriptions` | Active subscriptions that aren't set to end, the ones you can expect to renew |
| Monthly Recurring Revenue | `monthly_recurring_revenue` | Sum of active subscriptions' amounts, normalized to a month (a yearly plan counts 1/12). Excludes trials. Includes paused and past-due subscriptions until they end |
| Committed Monthly Recurring Revenue | `committed_monthly_recurring_revenue` | MRR from subscriptions that aren't set to end |
| Annual Recurring Revenue | `annual_recurring_revenue` | MRR × 12. API only |
| Committed Annual Recurring Revenue | `committed_annual_recurring_revenue` | Committed MRR × 12. API only |
| Trialing MRR Including Cancelations | `trial_monthly_recurring_revenue` | Monthly-normalized amount of subscriptions in a trial, including canceled trials |
| Trialing Monthly Recurring Revenue | `trial_committed_monthly_recurring_revenue` | Monthly-normalized amount of trials that aren't canceled |

## Checkouts

| Name | Slug | Definition |
| --- | --- | --- |
| Checkouts | `checkouts` | Checkout Sessions created in the interval, whatever their outcome |
| Succeeded Checkouts | `succeeded_checkouts` | Checkouts that reached `succeeded` |
| Checkouts Conversion Rate | `checkouts_conversion` | Succeeded checkouts divided by checkouts. 0 when there are none |

## Cancellations

| Name | Slug | Definition |
| --- | --- | --- |
| Canceled Subscriptions | `canceled_subscriptions` | Subscriptions canceled in the interval. They may stay active until the end of the paid period |
| Canceled Subscriptions - Customer Service | `canceled_subscriptions_customer_service` | Canceled with the reason customer service |
| Canceled Subscriptions - Low Quality | `canceled_subscriptions_low_quality` | Canceled with the reason low quality |
| Canceled Subscriptions - Missing Features | `canceled_subscriptions_missing_features` | Canceled with the reason missing features |
| Canceled Subscriptions - Switched Service | `canceled_subscriptions_switched_service` | Canceled with the reason switched service |
| Canceled Subscriptions - Too Complex | `canceled_subscriptions_too_complex` | Canceled with the reason too complex |
| Canceled Subscriptions - Too Expensive | `canceled_subscriptions_too_expensive` | Canceled with the reason too expensive |
| Canceled Subscriptions - Unused | `canceled_subscriptions_unused` | Canceled with the reason unused |
| Canceled Subscriptions - Other | `canceled_subscriptions_other` | Canceled with another reason or none |
| Churned Subscriptions | `churned_subscriptions` | Subscriptions that actually ended in the interval, when access stops |
| Churn Rate | `churn_rate` | Subscriptions canceled in the 30 days before the interval, divided by those active at the start of that window. With a yearly interval, the window is the year |

On **Analytics → Metrics**, the reason metrics are combined into one stacked chart labeled by reason: **Too Expensive**, **Missing Features**, **Switched Service**, **Unused**, **Customer Service**, **Low Quality**, **Too Complex** and **Other**. The group also shows **Active Subscriptions** and **Committed Subscriptions** to put churn in context.

## Unit economics

| Name | Slug | Definition |
| --- | --- | --- |
| Average Revenue Per User | `average_revenue_per_user` | MRR divided by the number of distinct subscribed customers. 0 when there are none |
| Lifetime Value | `ltv` | (ARPU − cost per user) ÷ churn rate. 0 when churn rate is 0 |

The group also shows **Churn Rate**.

## Costs

Cost metrics come from events with a `_cost` field. See [Cost insights](/features/cost-insights/introduction). They're stored with sub-cent precision.

| Name | Slug | Definition |
| --- | --- | --- |
| Costs | `costs` | Costs recorded in the interval |
| Cumulative Costs | `cumulative_costs` | Running total of costs from the start of the range |
| Cost Per User | `cost_per_user` | Costs in the interval divided by active users by event. For the whole range, total costs divided by active subscriptions |
| Gross Margin | `gross_margin` | Cumulative revenue minus cumulative costs |
| Gross Margin % | `gross_margin_percentage` | Gross margin as a share of cumulative revenue. 0 when there's no revenue |
| Cashflow | `cashflow` | Revenue minus costs within the interval, not cumulative |

## Usage

| Name | Slug | Definition |
| --- | --- | --- |
| Active User (By event) | `active_user_by_event` | Distinct customers with at least one ingested event in the interval |

## Seats

Seat metrics count assigned seats on [seat-based products](/features/seat-based-pricing).

| Name | Slug | Definition |
| --- | --- | --- |
| Active Customers | `seat_customers` | Distinct customers with at least one seat that isn't revoked |
| New Customers | `new_seat_customers` | Customers whose first seat was created in the interval |
| Churned Customers | `churned_seat_customers` | Customers whose last seat was revoked in the interval |
| Seat Count | `seats_total` | Seats assigned and not revoked at the end of the interval |
| Claimed Seats | `seats_claimed` | Seats claimed by a member. API only |
| Pending Seats | `seats_pending` | Seats assigned but not yet claimed. API only |
| Average Seats per Customer | `average_seats_per_customer` | Seat count divided by active customers |
| Seat Utilization Rate | `seat_utilization_rate` | Claimed seats divided by seat count |
