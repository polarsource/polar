A **Custom benefit** delivers a private note to customers after they buy. Use it for anything Polar doesn't automate: a booking link, onboarding instructions, a support email or a partner coupon code.

## What the customer gets

The note, rendered as Markdown, on the checkout confirmation page, in the purchase confirmation email and in the [Customer Portal](/features/customer-portal/introduction). The note is optional. Without one, the customer sees only the benefit's description.

## Create it

<Tabs>
  <Tab title="Dashboard">
    - Open **Products** → **Benefits**
    - Click **Create Benefit**
    - Choose **Custom** as the **Type**
    - Set the **Description**, the title customers see, e.g. "Onboarding call"
    - Write the **Private note**
    - Click **Create**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar benefits create --data '{
      "type": "custom",
      "description": "Onboarding call",
      "properties": { "note": "Book your call: https://cal.com/example/onboarding" }
    }'
    ```

    See [`polar benefits`](/integrate/cli/reference/benefits).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a Custom benefit called "Onboarding call" with the note "Book your call: https://cal.com/example/onboarding" in my Polar sandbox organization.
    ```

    Uses the `benefits_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

Then attach it to a product. See [Manage benefits](/features/benefits/introduction#attach-a-benefit-to-a-product).

## Options

| Dashboard | API property | Default |
| --- | --- | --- |
| **Private note** | `properties.note` | None |
| **Visibility** | `visibility` | `public` |
| **Metadata** | `metadata` | None |

## Customer experience

After paying, the customer sees the benefit's description with the note below it. The same note is in their confirmation email and stays available in the Customer Portal for as long as they hold the benefit.

## Revocation

When the benefit is revoked, for example when a subscription ends, the note disappears from the Customer Portal. Anything you delivered outside Polar, like a booked call or a shared document, is up to you to remove.

## Visibility

Configurable. A hidden Custom benefit is granted but never shown to the customer, so the note isn't delivered. Hide it only when your application reads the grant from the [customer state](/integrate/customer-state).

<Tip>
  To gate a feature in your application, use a [Feature Flag](/features/benefits/feature-flags) benefit. It's built for access checks and carries metadata.
</Tip>
