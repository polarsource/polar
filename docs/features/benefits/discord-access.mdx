A **Discord Invite benefit** adds a customer to your Discord server and gives them a role. Polar's bot handles the invitation and removes access again when the benefit is revoked.

## What the customer gets

Membership of your Discord server with the role you chose. Use one benefit per server and role. To offer different roles per plan, create a benefit for each role and attach each to its product.

## Create it

Connecting the server happens in the dashboard. Once it's connected, you can also create benefits for it from the CLI or your agent.

### Connect your Discord server

- Open **Catalog** → **Benefits**
- Click **Create Benefit** and choose **Discord Invite** as the **Type**
- Click **Connect your Discord server**
- In Discord, pick the server and approve the bot's permissions: **Manage Roles**, **Kick Members** and **Create Invite**

You're sent back to the form with the server connected. A benefit's server can't be changed later. Create another benefit to use another server.

### Create the benefit

<Tabs>
  <Tab title="Dashboard">
    - Choose the **Granted role**
    - Optionally check **Kick member on revocation**
    - Click **Create**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar benefits create --data '{
      "type": "discord",
      "description": "Members Discord",
      "properties": {
        "guild_id": "<discord_server_id>",
        "role_id": "<discord_role_id>",
        "kick_member": false
      }
    }'
    ```

    See [`polar benefits`](/integrate/cli/reference/benefits).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a Discord Invite benefit called "Members Discord" for my connected Discord server, granting the Member role, in my Polar sandbox organization.
    ```

    Uses the `benefits_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<Warning>
  Discord only lets the bot grant roles below its own. In Discord, open **Server Settings** → **Roles** and drag the Polar bot's role above every role you want to grant. Roles above it can't be selected.
</Warning>

## Options

| Dashboard | API property | Default |
| --- | --- | --- |
| **Connected Discord server** | `properties.guild_id` | Required |
| **Granted role** | `properties.role_id` | Required |
| **Kick member on revocation** | `properties.kick_member` | `false` in the dashboard, required in the API |

The API rejects a `guild_id` your organization hasn't connected, and a `role_id` that doesn't exist on that server.

## Customer experience

After paying, on the checkout confirmation page or in the [Customer Portal](/features/customer-portal/introduction), the customer:

1. Clicks **Connect Discord account** and authorizes Discord
2. Clicks **Request my invite**

Polar adds them to the server with the role. **Open Discord** takes them there. If they connected the wrong account, **Request new invite** lets them pick another one.

## Revocation

When the benefit is revoked, Polar removes the role. With `kick_member` enabled, it removes the member from the server instead.

## Visibility

Always visible. The customer has to connect their Discord account in the portal, so this benefit can't be hidden.
