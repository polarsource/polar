A **File Downloads benefit** gives customers access to files you upload to Polar: ebooks, design assets, installers, any file type. Customers download them from the Customer Portal.

## What the customer gets

Every enabled file in the benefit, each with a personal, signed download link that expires. Files you add later become available to existing customers too.

## Create it

<Tabs>
  <Tab title="Dashboard">
    - Open **Products** → **Benefits**
    - Click **Create Benefit**
    - Choose **File Downloads** as the **Type**
    - Set the **Description**, e.g. "Design kit"
    - Drop files on the upload area, or click it to browse
    - Click **Create** once the uploads finish
  </Tab>
  <Tab title="CLI">
    Upload the files in the dashboard or through the API first. The CLI can't upload files. Then:

    ```bash
    polar benefits create --data '{
      "type": "downloadables",
      "description": "Design kit",
      "properties": { "files": ["<file_id>"] }
    }'
    ```

    See [`polar benefits`](/integrate/cli/reference/benefits).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a File Downloads benefit called "Design kit" with my uploaded file design-kit.zip in my Polar sandbox organization.
    ```

    Uses the `files_list` and `benefits_create` operations of the [Polar MCP server](/integrate/mcp). The file must already be uploaded.
  </Tab>
</Tabs>

### Upload through the API

Uploads are multipart, straight to storage:

1. [Create the file](/api-reference/current/files/create-file) with `service: "downloadable"`, its `name`, `mime_type`, `size` and `upload.parts`, one entry per chunk. The response holds a presigned URL per part.
2. `PUT` each part to its URL and keep the returned `ETag`.
3. [Complete the upload](/api-reference/current/files/complete-file-upload) with the parts and their ETags.

Then pass the file's `id` in `properties.files`. A benefit needs at least one file.

## Options

| Dashboard | API property | Default |
| --- | --- | --- |
| Uploaded files, in order | `properties.files` | Required, at least one |
| Enabled toggle per file | `properties.archived` (`{ "<file_id>": true }` disables a file) | All enabled |

## Manage files

Open the benefit in **Products** → **Benefits** to manage its files:

- **Rename:** click the file name and edit it inline.
- **Reorder:** drag files into the order customers should see.
- **Download** or **Copy SHA256 Checksum:** from the file's menu. Share the checksum so customers can verify their download.
- **Disable:** turn off the file's toggle. It disappears from every customer's downloads, including existing customers. Turn it back on to restore access.
- **Delete:** from the file's menu.

<Warning>
  Deleting a file removes it for every customer who has the benefit, and can't be undone. Disable the file instead if you might need it again.
</Warning>

Adding a file or enabling one gives every current holder of the benefit access to it.

To see how often each file was downloaded, check the **Downloaders** and **Downloads** columns on the benefit's page. From the CLI, `polar benefits files <benefit_id>` lists `downloads` and `downloaders` per file. Your agent can do the same with `benefits_files`.

## Customer experience

After paying, the customer finds the files on the checkout confirmation page and in the [Customer Portal](/features/customer-portal/introduction), where they can download them for as long as they hold the benefit.

## Revocation

When the benefit is revoked, for example when a subscription ends, the files disappear from the customer's portal and new download links stop being issued.

## Visibility

Always visible. Customers download the files from the portal, so this benefit can't be hidden.

## Flagged files

Polar scans every uploaded file for malware. If a scan detects a threat, the file gets a **Malicious file detected** badge in your dashboard and every member of your organization receives an email.

<Warning>
  **Customers lose access to flagged files.** A flagged file is hidden from the Customer Portal and can no longer be downloaded, by your customers or by you. Other files in the benefit aren't affected.
</Warning>

Most detections are false positives on legitimate software, often unsigned installers, packed executables or tools that modify other programs. Start by finding out which case you're in:

1. **Check the detection.** The email names the detected threat. Copy the file's checksum from its menu and look it up on a multi-engine scanner such as [VirusTotal](https://www.virustotal.com) to see which antivirus engines flag it.
2. **If the file may really be infected,** rebuild it on a clean machine, upload the new version and delete the flagged file. Every upload is scanned again.
3. **If you believe it's a false positive,** report the file to the antivirus vendors that flag it through their false positive forms. Signing your executables with a code signing certificate also makes false positives less likely. Once a vendor clears the file, upload it again.
4. **Contact [Polar support](mailto:support@polar.sh)** with the file name and checksum. Polar can request a review of the scan result from its malware scanning provider.

<Note>
  Uploading the exact same file again usually gets it flagged again, until the antivirus vendors have updated their detections.
</Note>
