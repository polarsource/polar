The **Embedded Payment Method** opens a Polar-hosted card form on your site, as a modal or an inline iframe. The customer adds a card and Polar attaches it to the customer, as their default payment method unless you pass `setAsDefault: false`. Card details never touch your servers.

Use it in a [custom billing portal](/features/customer-portal/custom-portal), or anywhere customers need to update their card without leaving your app.

## Create a session token

Every embed is authenticated with a short-lived token for one customer. Create a [customer session](/api-reference/current/customer-sessions/create-customer-session) on your server, so your access token stays secret, and pass its `token` to the browser:

<CodeGroup>
```typescript TypeScript
const session = await polar.customerSessions.create({
  external_customer_id: "user_123",
});

return { token: session.token };
```

```python Python
session = polar.customer_sessions.create(external_customer_id="user_123")

return {"token": session.token}
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/customer-sessions/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "external_customer_id": "user_123" }' | jq -r .token
```
</CodeGroup>

The token starts with `polar_mst_`, expires after one hour and is scoped to that customer. Pass `customer_id` instead of `external_customer_id` to use Polar's ID. The examples use the sandbox and API version `2026-10`.

<Note>API only. Not available from the CLI or MCP server.</Note>

## Embed hosts

The embed only opens on a host you've allowed under **Settings → Embedding**, the same list as [Embedded checkout](/features/checkout/embed). See [Embed hosts](/features/checkout/embed-hosts) for the accepted formats.

If the page isn't on the list, the browser refuses to load the embed: it stays blank and the console shows a message naming `frame-ancestors`. An invalid or expired token has the same effect.

## Open as a modal

`PolarEmbedPaymentMethod.create()` opens the embed as a full-screen modal overlay.

```ts TypeScript
import { PolarEmbedPaymentMethod } from "@polar-sh/checkout/payment-method";

const embed = await PolarEmbedPaymentMethod.create({
  sessionToken: token,
});

embed.addEventListener("success", (event) => {
  console.log(event.detail.paymentMethodId);
});
```

`create()` options:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `sessionToken` | `string` | | **Required.** The customer session `token`. |
| `theme` | `'light' \| 'dark'` | `light` | Color scheme. |
| `setAsDefault` | `boolean` | `true` | Whether the new card becomes the customer's default payment method. |
| `returnUrl` | `string` | current URL | Where to return the customer after a [redirect-based method](#redirect-based-payment-methods). |
| `locale` | `string` | `en` | BCP 47 locale for the form, like `en` or `fr-FR`. Unsupported locales fall back to English. |
| `onLoaded` | `(event: CustomEvent) => void` | | Called on the `loaded` event. |

### Modal in React

Open the modal from a Client Component event handler:

```tsx React
"use client";
import { PolarEmbedPaymentMethod } from "@polar-sh/checkout/payment-method";

interface Props {
  sessionToken: string;
}

export function AddPaymentMethodButton({sessionToken}: Props) {
  const onClick = async () => {
    const embed = await PolarEmbedPaymentMethod.create({ sessionToken });
    embed.addEventListener("success", (event) => {
      console.log(event.detail.paymentMethodId);
    });
  };

  return <button onClick={onClick}>Add payment method</button>;
}
```

## Embed inline

Mount a borderless, auto-resizing iframe into an element you control:

```ts TypeScript
import { PolarEmbedPaymentMethod } from "@polar-sh/checkout/payment-method";

const embed = PolarEmbedPaymentMethod.createInline({
  sessionToken: token,
  element: document.getElementById("payment-method")!,
});

embed.addEventListener("success", (event) => {
  console.log(event.detail.paymentMethodId);
});
```

`createInline()` takes the same options as `create()`, except `returnUrl`, plus a required `element` to mount into.

### Inline in React

Use the `<PolarPaymentMethod />` component:

```tsx React
import { PolarPaymentMethod } from "@polar-sh/checkout/react/payment-method";

return (
  <PolarPaymentMethod
    sessionToken={token}
    onSuccess={(paymentMethodId) => console.log({ paymentMethodId })}
  />
);
```

| Prop | Description |
| --- | --- |
| `sessionToken` | **Required.** The customer session `token`. |
| `theme` | `light` or `dark`. Defaults to `light`. |
| `setAsDefault` | Whether the new card becomes the default. Defaults to `true`. |
| `locale` | BCP 47 locale for the form. |
| `onLoaded` | Called when the form is ready. |
| `onConfirmed` | Called when the customer submits the card. Disable your own close or cancel buttons until `onSuccess` or `onError`. |
| `onSuccess` | Called with the payment method ID once it's attached to the customer. |
| `onError` | Called with an error code when the form can't load: missing, expired or rejected token. |
| `className`, `style` | Applied to the wrapping `div`. |

## Use the script tag

Without a bundler, add the script and an element with `data-polar-payment-method`. Clicking the element opens the modal.

```html HTML
<button data-polar-payment-method="polar_mst_...">Add payment method</button>

<script
  defer
  data-auto-init
  src="https://cdn.jsdelivr.net/npm/@polar-sh/checkout@latest/dist/embed.global.js"
></script>
```

The same script powers [embedded checkout](/features/checkout/embed), so one tag covers both.

| Attribute | Value | Description |
| --- | --- | --- |
| `data-polar-payment-method` | `string` | **Required.** The session token. |
| `data-polar-payment-method-theme` | `light \| dark` | Theme override. |
| `data-polar-payment-method-set-as-default` | `true \| false` | Defaults to `true`. Pass `"false"` to keep the existing default. |
| `data-polar-payment-method-return-url` | `string` | Return URL for redirect-based methods. Defaults to the current page. |
| `data-polar-payment-method-locale` | `string` | BCP 47 locale, like `en` or `fr-FR`. |

## Localization

Pass a BCP 47 locale with the `locale` option or the `data-polar-payment-method-locale` attribute:

```ts TypeScript
const embed = await PolarEmbedPaymentMethod.create({
  sessionToken: token,
  locale: "fr-FR",
});
```

Without it, the embed is in English. Unsupported locales fall back to English. See [Localization](/features/checkout/localization#supported-languages) for the supported languages.

## Events

Events are cancelable `CustomEvent`s on the `embed` instance. Call `event.preventDefault()` to skip the default action.

| Event | Detail | Default action |
| --- | --- | --- |
| `loaded` | | Removes the loading spinner once the iframe is ready. |
| `close` | | Removes the iframe, unless a `confirmed` payment is pending. |
| `confirmed` | | Blocks closing the modal while the card is processed. |
| `success` | `{ paymentMethodId: string }` | Closes the modal. Call `preventDefault()` to keep it open. |
| `error` | `{ code: 'invalid_request' \| 'unauthorized' \| 'processing_failed' \| 'unknown' }` | Allows closing the modal again. |

To check the result from your backend, list the customer's saved methods with `polar customers list_payment_methods_external user_123` or [List Customer Payment Methods](/api-reference/current/customers/list-customer-payment-methods-by-external-id). The MCP operation is `customers_list_payment_methods_external`.

## Redirect-based payment methods

Some payment methods authorize on the provider's site. The whole tab navigates away and back to `returnUrl`, which defaults to the page the embed was opened from, so the modal doesn't survive the round trip.

Read the outcome on the returned page with the static `getRedirectResult()`:

```ts TypeScript
import { PolarEmbedPaymentMethod } from "@polar-sh/checkout/payment-method";

const result = PolarEmbedPaymentMethod.getRedirectResult();
// result: { status: 'succeeded' | 'failed' } | null

if (result?.status === "succeeded") {
  // refresh the customer's payment methods
}
```

In React, use the `usePaymentMethodRedirectResult` hook:

```tsx React
import { usePaymentMethodRedirectResult } from "@polar-sh/checkout/react/payment-method";

usePaymentMethodRedirectResult({
  onSuccess: () => console.log("Payment method added"),
  onError: () => console.error("Could not add payment method"),
});
```

Either way, the status query parameter is removed from the URL, so a refresh doesn't show a stale result. Cards, including 3D Secure, complete inside the embed and never take this path.
