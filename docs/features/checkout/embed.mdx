**Embedded checkout** opens the Polar checkout as a full-screen overlay on your page, instead of redirecting the customer to Polar. It's the same hosted checkout, loaded in an iframe on top of your site, with a spinner until it's ready.

Before embedding, add your site to the allowed [embed hosts](/features/checkout/embed-hosts). The checkout only opens on hosts you've listed.

## Add the snippet

The snippet works on any site or CMS that accepts HTML.

1. Create a [Checkout Link](/features/checkout/links).
2. Open the link, select the **Embed** tab and click **Copy**.
3. Paste the snippet into your page.

The snippet looks like this, with your link's URL in place of `__CHECKOUT_LINK__`:

```html HTML
<a
  href="__CHECKOUT_LINK__"
  data-polar-checkout
  data-polar-checkout-theme="light"
>
  Purchase
</a>

<script
  defer
  data-auto-init
  src="https://cdn.jsdelivr.net/npm/@polar-sh/checkout@latest/dist/embed.global.js"
></script>
```

Clicking the element opens the checkout. Style it however you want, as long as it keeps the `data-polar-checkout` attribute. On an element without `href`, such as a `<button>`, put the URL in the attribute: `data-polar-checkout="__CHECKOUT_LINK__"`.

<Tip>
  The snippet loads `@latest`. Replace it with a fixed version of `@polar-sh/checkout` to control when you upgrade.
</Tip>

The script also exposes the embed class as `window.Polar.EmbedCheckout`, for pages without a bundler.

## Use the library

In a JavaScript app, install the library instead of adding a script tag:

<CodeGroup>
```bash npm
npm install @polar-sh/checkout
```

```bash pnpm
pnpm add @polar-sh/checkout
```

```bash yarn
yarn add @polar-sh/checkout
```

```bash bun
bun add @polar-sh/checkout
```
</CodeGroup>

Call `PolarEmbedCheckout.init()` once to wire up every element with `data-polar-checkout`. In React:

```tsx React
import { PolarEmbedCheckout } from "@polar-sh/checkout/embed";
import { useEffect } from "react";

export function PurchaseLink() {
  useEffect(() => {
    PolarEmbedCheckout.init();
  }, []);

  return (
    <a href="__CHECKOUT_LINK__" data-polar-checkout data-polar-checkout-theme="light">
      Purchase
    </a>
  );
}
```

## Open the checkout from code

`PolarEmbedCheckout.create()` opens the checkout and resolves once it has loaded:

```ts TypeScript
import { PolarEmbedCheckout } from "@polar-sh/checkout/embed";

const checkout = await PolarEmbedCheckout.create("__CHECKOUT_LINK__", {
  theme: "dark",
  onLoaded: () => console.log("Checkout loaded"),
});

checkout.addEventListener("success", (event) => {
  if (!event.detail.redirect) {
    showThankYou();
  }
});

// Later, to close it yourself:
checkout.close();
```

| Option | Description |
| --- | --- |
| `theme` | `"light"` or `"dark"`. Defaults to `light`. |
| `onLoaded` | Called when the checkout has loaded. Prefer it over a `loaded` listener, which can miss a fast load. |

## Events

Events are cancelable `CustomEvent`s on the checkout instance. Call `event.preventDefault()` to skip the default action.

| Event | `event.detail` | Default action |
| --- | --- | --- |
| `loaded` | | Removes the loading spinner. |
| `close` | | Removes the overlay, unless the checkout is processing a payment. |
| `confirmed` | | Blocks closing while the payment is processed. |
| `success` | `successURL`, `redirect` | Allows closing again. If `redirect` is `true`, sends the page to `successURL`. |

Grant access from [webhooks](/integrate/webhooks/events) or the [customer state](/integrate/customer-state), not from the `success` event.

## Embed a checkout session

You can embed a [Checkout Session](/features/checkout/session) URL instead of a link. Set `embed_origin` when you create the session, to the origin of the page that embeds it:

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [product.id],
  external_customer_id: "user_123",
  embed_origin: "https://example.com",
});

// Pass checkout.url to PolarEmbedCheckout.create() in the browser
```

```python Python
checkout = polar.checkouts.create(
    products=[product.id],
    external_customer_id="user_123",
    embed_origin="https://example.com",
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "products": ["'"$PRODUCT_ID"'"],
    "external_customer_id": "user_123",
    "embed_origin": "https://example.com"
  }'
```
</CodeGroup>

**Why:** the checkout sends its `close`, `confirmed` and `success` messages only to the origin stored on the session. Checkout Links don't need this: the script adds your page's origin when it opens the link. The examples use the sandbox and API version `2026-10`.

## Theme and language

The embedded checkout is the hosted checkout, so the same query parameters apply: `theme` and, with [localization](/features/checkout/localization) on, `locale`.

AI agents in the browser can't use the [checkout tools](/features/checkout/agents) on an embedded checkout. Those are only on the hosted page.

## Embed hosts

The checkout opens only on hosts listed under **Settings → Embedding**. If the overlay stays blank and the browser console mentions `frame-ancestors`, the page's host isn't on the list. See [Embed hosts](/features/checkout/embed-hosts) for the format and the API field.

## Enable wallets in Embedded Checkout

[Wallets](/features/checkout/payment-methods#cards-and-wallets) such as Apple Pay and Google Pay appear in an embedded checkout only on hosts under a [verified domain](/features/domains). On Polar's hosted checkout, they work with no setup.

To enable them:

- Verify your domain under **Settings → Domains**
- Open **Settings → Embedding**
- Add each host that embeds the checkout, such as `shop.example.com`

A wildcard entry like `*.example.com` doesn't enable wallets. Add each subdomain on its own.

Each host in the list shows its wallet status. A host under a verified domain shows **Wallet payments pending** until your organization can accept payments.
