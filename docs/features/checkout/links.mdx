A **Checkout Link** is a permanent URL that opens a new checkout session each time someone visits it. Create it once, then put it on a pricing page, in an email or behind a button. No code needed.

Each visit creates a fresh Checkout Session from the link's settings and redirects the customer to it. Share the link, never the session URL behind it: sessions expire after 24 hours. See [Checkout](/concepts/checkout) for how links and sessions compare.

<Tip>
  Know who the customer is, or need per-customer prices or metadata? Create a [Checkout Session](/features/checkout/session) from your backend instead.
</Tip>

## Create a Checkout Link

<Tabs>
  <Tab title="Dashboard">
    - Open **Catalog → Checkout Links**
    - Click **+**
    - Add a **Label** and select one or more **Products**
    - Click **Create Link**, then copy the URL from the **Link** tab
  </Tab>
  <Tab title="CLI">
    ```bash
    polar checkout_links create --payment-processor stripe \
      --products <product_id> \
      --label "Pricing page" \
      --success-url "https://example.com/billing?checkout_id={CHECKOUT_ID}"
    ```

    `--payment-processor stripe` is required. Repeat `--products` to offer several products. See [`polar checkout_links`](/integrate/cli/reference/checkout_links).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a Checkout Link for my Pro product in my Polar sandbox, labeled "Pricing page", that returns customers to https://example.com/billing.
    ```

    Uses the `checkout_links_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

The response's `url` is the link to share. From the API, send the same fields to [`POST /v1/checkout-links/`](/api-reference/current/checkout-links/create-checkout-link):

<CodeGroup>
```typescript TypeScript
const link = await polar.checkoutLinks.create({
  payment_processor: "stripe",
  products: [product.id],
  label: "Pricing page",
  success_url: "https://example.com/billing?checkout_id={CHECKOUT_ID}",
});

console.log(link.url);
```

```python Python
link = polar.checkout_links.create(
    payment_processor="stripe",
    products=[product.id],
    label="Pricing page",
    success_url="https://example.com/billing?checkout_id={CHECKOUT_ID}",
)

print(link.url)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkout-links/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "payment_processor": "stripe",
    "products": ["'"$PRODUCT_ID"'"],
    "label": "Pricing page",
    "success_url": "https://example.com/billing?checkout_id={CHECKOUT_ID}"
  }'
```
</CodeGroup>

The examples use the sandbox and API version `2026-10`. See the [quickstart](/quickstart/overview#prerequisites) for the client setup.

## Link settings

| Dashboard label | API field | What it does |
| --- | --- | --- |
| **Label** | `label` | Internal name to tell links apart. Customers don't see it. |
| **Products** | `products` | Products offered, in this order. The first is preselected. With several products, the customer picks one: products aren't bundled into one order. |
| **Success URL** | `success_url` | Where the customer goes after paying. Add `checkout_id={CHECKOUT_ID}` and Polar fills in the session ID. Without it, the customer stays on Polar's confirmation page. |
| **Return URL** | `return_url` | Shows a back button on the checkout that returns to this URL. |
| **Preset discount** | `discount_id` | Applied automatically when the checkout opens. A discount that no longer applies is ignored. |
| **Allow discount codes** | `allow_discount_codes` | Lets the customer enter a code. With a preset discount, the customer can't change it when this is off. |
| **Require billing address** | `require_billing_address` | Asks for the full address instead of only the country. Customers in the US always enter their full address. |
| **Lock number of seats** | `seats` | Locks [seat-based](/features/seat-based-pricing) products to this seat count. Ignored if the products no longer allow it. |
| (API and CLI only) | `units` | Locks [unit-based](/features/unit-based-pricing) products to this unit count. |
| **Free Trial Configuration** | `trial_interval`, `trial_interval_count` | Overrides the products' own trial for sessions from this link. Shown for recurring products. |
| **Metadata** | `metadata` | Copied to each session, and from there to the order and subscription. |

<Note>
  Discounts without a code can only be applied through a link's preset discount or a [Checkout Session](/features/checkout/session#discounts). See [Discounts](/features/discounts).
</Note>

## Query parameters

Add query parameters to the link URL to change one visit without changing the link.

| Parameter | What it does |
| --- | --- |
| `product_id` | Preselect one of the link's products. The customer can still switch. |
| `customer_email` | Prefill the email. |
| `customer_name` | Prefill the name. |
| `discount_code` | Prefill the discount code field. Only works with discounts that have a code. Unlike a preset discount, the customer sees the code. |
| `amount` | Prefill the amount of a pay-what-you-want price. |
| `custom_field_data.{slug}` | Prefill a [custom field](/features/custom-fields) by its slug. |
| `locale` | Set the checkout language, as a BCP 47 tag like `fr` or `pt-PT`. Only applies when [localization](/features/checkout/localization) is enabled. |
| `theme` | Force `light` or `dark`. By default, the theme follows the customer's system. |

```text
<checkout_link_url>?customer_email=jane@example.com&locale=fr&theme=dark
```

### Store attribution and reference metadata

These parameters are saved in the session's [`metadata`](/api-reference/current/checkouts/get-checkout-session#response-metadata), and copied to the order and subscription:

| Parameter | Use it for |
| --- | --- |
| `reference_id` | Your own reference for the visit |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` | Campaign attribution |

## Embed the link

To open the checkout on your own site, open the link and select the **Embed** tab, then click **Copy**. See [Embedded checkout](/features/checkout/embed).

## Find the sessions a link created

Every visit creates a session you can inspect, filtered by product.

In the dashboard, open **Sales → Checkouts** and filter by **Product** and **Status** (**Open**, **Confirmed**, **Succeeded**, **Expired** or **Failed**).

From the CLI:

```bash
polar checkouts list --product-id <product_id> --status succeeded
```

## From the CLI or your agent

| Task | CLI | MCP operation |
| --- | --- | --- |
| Create a link | `polar checkout_links create` | `checkout_links_create` |
| List links | `polar checkout_links list` | `checkout_links_list` |
| Get a link | `polar checkout_links get <id>` | `checkout_links_get` |
| Update a link | `polar checkout_links update <id>` | `checkout_links_update` |
| Delete a link | `polar checkout_links delete <id>` | `checkout_links_delete` |

Deleting a link stops its URL from working.
