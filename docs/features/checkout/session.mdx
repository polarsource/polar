A **Checkout Session** is one purchase attempt. Create it from your backend when you know who's buying, then redirect the customer to its `url`. Sessions expire after 24 hours. For a permanent URL that needs no code, use a [Checkout Link](/features/checkout/links). See [Checkout](/concepts/checkout) for how the two compare.

<Note>API only. Not available from the CLI or MCP server. You can list and inspect sessions from both, see [Inspect sessions](#inspect-sessions).</Note>

The examples use the sandbox client from the [quickstart overview](/quickstart/overview#prerequisites), on API version `2026-10`.

## Create a session

Pass the products to offer and your user's ID, then redirect to `url`:

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [product.id],
  external_customer_id: "user_123",
  success_url: "https://example.com/billing?checkout_id={CHECKOUT_ID}",
});

redirect(checkout.url);
```

```python Python
checkout = polar.checkouts.create(
    products=[product.id],
    external_customer_id="user_123",
    success_url="https://example.com/billing?checkout_id={CHECKOUT_ID}",
)

return redirect(checkout.url)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "products": ["'"$PRODUCT_ID"'"],
    "external_customer_id": "user_123",
    "success_url": "https://example.com/billing?checkout_id={CHECKOUT_ID}"
  }'
```
</CodeGroup>

With several IDs in `products`, the checkout shows each product as an option, in that order, with the first one preselected. The customer buys one of them. Products aren't bundled into a single order.

<Visibility for="agents">
  Rules for creating checkout sessions:

  - Create sessions on the server. The access token must never reach the browser.
  - Pass the application's user ID as `external_customer_id`. Don't store Polar customer IDs.
  - Create a new session each time the user clicks to buy. Don't cache or share session URLs: they expire after 24 hours.
  - When the request comes from your backend, forward the end user's IP as `customer_ip_address`.
  - Fulfill access from the `customer.state_changed` or `order.paid` webhook, not from the `success_url` redirect.
  - Over HTTP, this is `POST /v1/checkouts/` with the `Polar-Version: 2026-10` header.
</Visibility>

## Redirect and return

| Field | What it does |
| --- | --- |
| `success_url` | Where the customer goes after paying. `{CHECKOUT_ID}` is replaced with the session ID, so you can fetch it with [`GET /v1/checkouts/{id}`](/api-reference/current/checkouts/get-checkout-session). Without it, the customer stays on Polar's confirmation page. |
| `return_url` | Shows a back button on the checkout that returns to this URL. |

The redirect to `success_url` isn't proof of payment. Grant access from [webhooks](/integrate/webhooks/events) or the [customer state](/integrate/customer-state).

## External customer ID

Set `external_customer_id` to your user's ID. If a customer with that external ID exists, the order is linked to them. Otherwise Polar creates the customer with that external ID when the checkout succeeds. To use Polar's ID instead, pass `customer_id`.

When the session resolves to an existing customer, their email is prefilled and the email field is locked. An `external_customer_id` that matches no customer leaves the email editable. See [External ID](/concepts/customers#external-id).

## Prefill customer details

| Field | Notes |
| --- | --- |
| `customer_email`, `customer_name` | Prefilled and editable. |
| `customer_billing_name`, `customer_billing_address`, `customer_tax_id` | Prefill invoice details. Prefilling an address turns on `require_billing_address`. |
| `require_billing_address` | Ask for the full address instead of only the country. Customers in the US always enter their full address. |
| `is_business_customer` | Ask for a billing name and full address, for B2B purchases. |
| `custom_field_data` | Prefill [custom fields](/features/custom-fields), keyed by slug. |

## Discounts

Set `discount_id` to apply a discount automatically. `allow_discount_codes` controls whether the customer can enter a code. With a preset discount and codes turned off, the customer can't change the discount. See [Discounts](/features/discounts).

## Trials

A product's trial applies by default. Set `allow_trial: false` to remove it for this session, or set `trial_interval` and `trial_interval_count` to override its length. See [Trials](/features/subscriptions/trials).

## Seats, units and amounts

| Field | Applies to |
| --- | --- |
| `seats`, `min_seats`, `max_seats` | [Seat-based](/features/seat-based-pricing) prices |
| `units`, `min_units`, `max_units` | [Unit-based](/features/unit-based-pricing) prices |
| `amount` | Pay-what-you-want prices: the prefilled amount, in cents |

## Ad-hoc prices

**Ad-hoc prices** exist only for one session. Use them for per-customer pricing without changing your catalog. Pass `prices`, keyed by product ID:

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [product.id],
  prices: {
    [product.id]: [
      { amount_type: "fixed", price_amount: 10000, price_currency: "usd" },
    ],
  },
});
```

```python Python
checkout = polar.checkouts.create(
    products=[product.id],
    prices={
        product.id: [
            {"amount_type": "fixed", "price_amount": 10000, "price_currency": "usd"},
        ],
    },
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "products": ["'"$PRODUCT_ID"'"],
    "prices": {
      "'"$PRODUCT_ID"'": [
        { "amount_type": "fixed", "price_amount": 10000, "price_currency": "usd" }
      ]
    }
  }'
```
</CodeGroup>

The `amount_type` is one of `fixed`, `custom` (pay what you want), `seat_based`, `unit_based`, `metered_unit` or `metered_tiers`. A free price is `fixed` with `price_amount: 0`. Combine at most one `fixed` and one `seat_based` price, or use one `custom` price alone, plus any number of metered prices.

Ad-hoc prices have `source: "ad_hoc"` in responses. Catalog prices have `source: "catalog"`.

## Currency and customer IP address

Without `currency`, Polar picks it from the customer's country, based on their IP, and falls back to your organization's default currency. The IP also prefills the billing country, which drives tax. See [Products](/features/products) for multi-currency prices.

When you create sessions from a backend, proxy or edge function, Polar sees your server's IP. Forward the customer's IP as `customer_ip_address`:

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [product.id],
  customer_ip_address: request.headers.get("CF-Connecting-IP") ?? undefined,
});
```

```python Python
checkout = polar.checkouts.create(
    products=[product.id],
    customer_ip_address=request.headers.get("X-Forwarded-For", "").split(",")[0].strip() or None,
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "products": ["'"$PRODUCT_ID"'"], "customer_ip_address": "203.0.113.7" }'
```
</CodeGroup>

The header depends on your runtime: `CF-Connecting-IP` on Cloudflare Workers, `X-Forwarded-For` behind most proxies. With `customer_ip_address` set, you don't need to set the billing country yourself.

## Metadata

| Field | Copied to |
| --- | --- |
| `metadata` | The order and subscription created by the checkout |
| `customer_metadata` | The customer created by the checkout |

## Upgrade a free subscription

Set `subscription_id` to the ID of a subscription on a free price. When the checkout succeeds, Polar upgrades that subscription instead of creating a new one.

## Embedding and language

- `embed_origin`: the origin of the page that embeds the checkout, like `https://example.com`. Required to embed a session. See [Embedded checkout](/features/checkout/embed#embed-a-checkout-session).
- `locale`: the checkout language, when [localization](/features/checkout/localization) is enabled.
- Append `?theme=dark` or `?theme=light` to the session `url` to force a theme.

## Update a session

Change an open session from your backend with [`PATCH /v1/checkouts/{id}`](/api-reference/current/checkouts/update-checkout-session), for example to switch the product or apply a discount:

<CodeGroup>
```typescript TypeScript
await polar.checkouts.update(checkout.id, { discount_id: discount.id });
```

```python Python
polar.checkouts.update(checkout.id, discount_id=discount.id)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/checkouts/$CHECKOUT_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "discount_id": "'"$DISCOUNT_ID"'" }'
```
</CodeGroup>

The `/v1/checkouts/client/{client_secret}` endpoints are what Polar's checkout page calls. They take the session's `client_secret` instead of an access token. Use them only to build your own checkout UI.

## Session lifecycle

A session starts `open` and expires 24 hours after creation (`expires_at`). Paying moves it to `confirmed`, then `succeeded` or `failed`. A session never completed becomes `expired`.

| Dashboard | API `status` |
| --- | --- |
| **Open** | `open` |
| **Confirmed** | `confirmed` |
| **Succeeded** | `succeeded` |
| **Expired** | `expired` |
| **Failed** | `failed` |

## Inspect sessions

Find sessions in the dashboard, from the CLI or with your agent:

<Tabs>
  <Tab title="Dashboard">
    - Open **Sales → Checkouts**
    - Filter by **Status**, **Product** or **Customer**, or search
    - Select a session
  </Tab>
  <Tab title="CLI">
    ```bash
    polar checkouts list --external-customer-id user_123 --status open
    polar checkouts get <checkout_id>
    ```

    See [`polar checkouts`](/integrate/cli/reference/checkouts).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    List the open checkout sessions for user_123 in my Polar sandbox.
    ```

    Uses the `checkouts_list` and `checkouts_get` operations of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>
