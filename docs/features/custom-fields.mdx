**Custom fields** add your own inputs to the checkout form: a terms checkbox, a newsletter opt-in, a "How did you hear about us?" select. You define fields once for your organization, then attach them to products.

The answers are stored under `custom_field_data` on the checkout, order and subscription, keyed by each field's slug.

## Field types

| Dashboard | API `type` | Input | Stored as | Constraints (`properties`) |
| --- | --- | --- | --- | --- |
| **Text** | `text` | Text input, or a textarea | String | `textarea`, `min_length`, `max_length` |
| **Number** | `number` | Number input | Whole number (32-bit integer) | `ge` (minimum), `le` (maximum) |
| **Date** | `date` | Date picker | ISO 8601 date | `ge`, `le`, as Unix timestamps in the API |
| **Checkbox** | `checkbox` | Checkbox | `true` or `false` | A required checkbox must be checked |
| **Select** | `select` | Dropdown | The option's `value` | `options`: a list of `{ "value", "label" }`, at least one |

Every type also takes a **Label**, **Help text** and **Placeholder** (`form_label`, `form_help_text` and `form_placeholder` in `properties`). The label and help text support basic Markdown, including links. Without a `form_label`, the field's name is the label.

The type can't be changed after creation.

## Create a field

<Tabs>
  <Tab title="Dashboard">
    - Open **Settings → Custom Fields**
    - Click **New**
    - Pick a **Type**, then set the **Slug** and **Name**
    - Optionally, set **Label**, **Help text** and **Placeholder** under **Form input options**, and limits under **Validation constraints**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar custom_fields create --type select --slug source --name "Source" \
      --properties '{"form_label":"How did you hear about us?","options":[{"value":"social_media","label":"Social media"},{"value":"friend","label":"A friend"}]}'
    ```

    See [`polar custom_fields`](/integrate/cli/reference/custom_fields).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a select custom field "source" in my Polar sandbox asking "How did you hear about us?", with the options Social media and A friend.
    ```

    Uses the `custom_fields_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

The **slug** is the key the answer is stored under. It's unique within your organization and takes lowercase letters, numbers, hyphens and underscores. You can rename it later: Polar updates the answers already stored on checkouts, orders and subscriptions.

The **name** identifies the field in your dashboard.

## Add the field to a product

A field only appears on the checkout of products it's attached to. Mark it required to block the checkout until it's filled in. A required checkbox must be checked, which suits terms acceptance.

<Tabs>
  <Tab title="Dashboard">
    - Open the product under **Products**
    - In the **Checkout Page** section, select the field under **Checkout Fields**
    - Toggle **Required** if needed, then save
  </Tab>
  <Tab title="CLI">
    ```bash
    polar products update <product_id> \
      --attached-custom-fields '[{"custom_field_id":"<custom_field_id>","required":true}]'
    ```

    The list replaces the product's attached fields. See [`polar products`](/integrate/cli/reference/products).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Attach the "source" custom field to my Pro product in my Polar sandbox and make it required.
    ```

    Uses the `products_update` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

## Prefill answers

- On a [Checkout Session](/features/checkout/session), pass `custom_field_data` keyed by slug: `{ "source": "friend" }`.
- On a [Checkout Link](/features/checkout/links#query-parameters), add `custom_field_data.{slug}` to the URL: `?custom_field_data.source=friend`.

## Read the answers

In the dashboard, open an order or subscription under **Sales**. The answers are in its **Custom Fields** section.

From the API, read `custom_field_data` on the [order](/api-reference/current/orders/get-order), [subscription](/api-reference/current/subscriptions/get-subscription) or checkout. The `order.created` and `subscription.created` webhooks include it too.

<CodeGroup>
```typescript TypeScript
const order = await polar.orders.get(orderId);

console.log(order.custom_field_data);
// { "terms": true, "source": "social_media" }
```

```python Python
order = polar.orders.get(order_id)

print(order.custom_field_data)
# {"terms": True, "source": "social_media"}
```

```bash cURL
curl https://sandbox-api.polar.sh/v1/orders/$ORDER_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" | jq .custom_field_data
```
</CodeGroup>

From the CLI: `polar orders get <order_id> --fields custom_field_data`. The examples use the sandbox and API version `2026-10`.

## From the CLI or your agent

| Task | CLI | MCP operation |
| --- | --- | --- |
| Create a field | `polar custom_fields create` | `custom_fields_create` |
| List fields | `polar custom_fields list` | `custom_fields_list` |
| Get a field | `polar custom_fields get <id>` | `custom_fields_get` |
| Update a field | `polar custom_fields update <id> --type <type>` | `custom_fields_update` |
| Delete a field | `polar custom_fields delete <id>` | `custom_fields_delete` |
| Attach to a product | `polar products update <id> --attached-custom-fields '[...]'` | `products_update` |

`polar custom_fields update` requires `--type`, set to the field's current type.
