Customers reach the [Customer Portal](/features/customer-portal/introduction) in three ways: the public URL, a pre-authenticated link from you or your app, or the emails Polar sends them.

## The portal URL

Every organization's portal lives at:

| Environment | URL |
| --- | --- |
| Production | `https://polar.sh/<org-slug>/portal` |
| Sandbox | `https://sandbox.polar.sh/<org-slug>/portal` |

To sign in:

1. The customer enters the email they bought with.
2. Polar emails them a 6-digit code, valid for 30 minutes.
3. They enter the code and land in the portal.

Use this URL where you need a stable link: your website footer, help center or support replies.

## Copy a link from the dashboard

To send one customer straight into their portal, for example from a support conversation:

- Open **Customers** and select the customer
- Open the **⋮** menu and click **Copy Customer Portal**
- Paste the link to the customer. It signs them in without an email code and expires after one hour

## Pre-authenticated links

When the customer is already signed in to your app, skip the email code. Create a **customer session** on your server and redirect the customer to its `customer_portal_url`:

<CodeGroup>
```typescript TypeScript
const session = await polar.customerSessions.create({
  external_customer_id: "user_123",
  return_url: "https://example.com/account",
});

redirect(session.customer_portal_url);
```

```python Python
session = polar.customer_sessions.create(
    external_customer_id="user_123",
    return_url="https://example.com/account",
)

return redirect(session.customer_portal_url)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/customer-sessions/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "external_customer_id": "user_123",
    "return_url": "https://example.com/account"
  }' | jq -r .customer_portal_url
```
</CodeGroup>

| Field | What it does |
| --- | --- |
| `external_customer_id` or `customer_id` | The customer, by your user ID or Polar's ID. |
| `return_url` | Shows a back button in the portal that returns to this URL. |
| `member_id` or `external_member_id` | For [team customers](/concepts/customers#individuals-and-teams), the member to sign in as. Without it, the session is for the customer's owner. |

The session expires after one hour. Create it when the customer clicks, and don't store the URL. The examples use the sandbox and API version `2026-10`.

<Note>Creating a customer session is API only. Not available from the CLI or MCP server. For a one-off link, [copy it from the dashboard](#copy-a-link-from-the-dashboard).</Note>

<Visibility for="agents">
  Create customer sessions on the server, with the user's ID as `external_customer_id`, right before redirecting. Never store or log `customer_portal_url` or `token`: either one signs the customer in for an hour. Over HTTP, this is `POST /v1/customer-sessions/` with the `Polar-Version: 2026-10` header.
</Visibility>

### With a framework adapter

The [Next.js adapter](/integrate/sdk/adapters/nextjs) turns this into one route handler:

```typescript app/portal/route.ts
import { CustomerPortal } from "@polar-sh/nextjs";

export const GET = CustomerPortal({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  getExternalCustomerId: async (req) => getUserIdFromSession(req),
  returnUrl: "https://example.com/account",
  environment: "sandbox",
});
```

Link to `/portal` from your app, and the customer lands in the portal signed in. Use `environment: "production"` when you go live. Other [adapters](/integrate/sdk/adapters/introduction) offer a Customer Portal handler too, but some take Polar's customer ID (`getCustomerId`) instead of yours. Check the adapter's page.

## Emails Polar sends

Most emails Polar sends your customers link to the portal, including:

- Order and subscription confirmations
- Renewal and trial conversion reminders
- Past-due payment and card expiring notices
- Subscription updated, paused, resumed, canceled and revoked notices

You choose which emails are sent under **Settings → Customer Notifications**. Turning an email off also removes that path to the portal, so keep a link in your own app.
