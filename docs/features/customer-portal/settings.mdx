Portal settings control what customers can change on their own in the [Customer Portal](/features/customer-portal/introduction). They live under **Settings → Customer Portal**, grouped as in the dashboard.

Each setting applies to the hosted portal and to the [Customer Portal API](/features/customer-portal/custom-portal), so a portal you build yourself follows the same rules. **Show metered usage** is the exception: it only hides the **Usage** page.

None of these settings limit you. Your backend can always make the same changes with the [Update Subscription](/api-reference/current/subscriptions/update-subscription) and [Update Customer](/api-reference/current/customers/update-customer) endpoints.

## Subscriptions

| Setting | API key | Default |
| --- | --- | --- |
| **Enable subscription plan changes** | `subscription.update_plan` | On |
| **Enable subscription unit changes** | `subscription.update_units` | Off |
| **Enable subscription seat management** | `subscription.update_seats` | On |
| **Enable subscription pausing** | `subscription.pause` | Off |

### Enable subscription plan changes

Lets customers switch to another product: upgrade, downgrade or move to a different plan. Changes follow your [proration settings](/features/subscriptions/proration). Turn it off if plan changes go through your own app.

### Enable subscription unit changes

Lets customers change the number of units on a subscription with a [unit-based price](/features/unit-based-pricing).

### Enable subscription seat management

Lets customers change the number of seats on a [seat-based](/features/seat-based-pricing) subscription, and assign or revoke seats for their teammates. Turned off, the portal hides seat management, and the Customer Portal API rejects seat count changes.

### Enable subscription pausing

Lets customers pause their subscription and resume it later. A paused subscription stops billing at the end of the current period and revokes benefits until it resumes. Resuming starts a new billing period and charges right away. See [Pause and resume](/features/subscriptions/manage#pause-and-resume).

## Account

| Setting | API key | Default |
| --- | --- | --- |
| **Allow email address changes** | `customer.allow_email_change` | Off |
| **Show metered usage** | `usage.show` | On |

### Allow email address changes

Lets individual customers change their email address. The change takes effect once they click the confirmation link sent to the new address.

When it's on, listen for the [`customer.updated`](/api-reference/current/customer_updated) webhook to sync the new email into your own user records.

### Show metered usage

Shows the **Usage** page, with the customer's consumption per [meter](/features/usage-based-billing/meters). Turned off, the page is hidden, but the [customer meters endpoints](/api-reference/current/customer_meters/list-customer-meters) keep working.

## Change settings in the dashboard

- Open **Settings → Customer Portal**
- Turn each switch on or off. Changes save automatically

## Change settings from the API

Send `customer_portal_settings` to [Update Organization](/api-reference/current/organizations/update-organization). The `usage` and `subscription` objects are required, with `show`, `update_plan` and `update_seats`. The examples use the sandbox and API version `2026-10`:

<CodeGroup>
```typescript TypeScript
await polar.organizations.update(organizationId, {
  customer_portal_settings: {
    usage: { show: true },
    subscription: { update_plan: true, update_seats: true, update_units: false, pause: true },
    customer: { allow_email_change: false },
  },
});
```

```python Python
polar.organizations.update(
    organization_id,
    customer_portal_settings={
        "usage": {"show": True},
        "subscription": {
            "update_plan": True,
            "update_seats": True,
            "update_units": False,
            "pause": True,
        },
        "customer": {"allow_email_change": False},
    },
)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/organizations/$ORGANIZATION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_portal_settings": {
      "usage": { "show": true },
      "subscription": { "update_plan": true, "update_seats": true, "update_units": false, "pause": true },
      "customer": { "allow_email_change": false }
    }
  }'
```
</CodeGroup>

<Note>Dashboard and API only. Not available from the CLI or MCP server. To read the current settings, run `polar organizations get <organization_id> --fields customer_portal_settings` or use the `organizations_get` MCP operation.</Note>
