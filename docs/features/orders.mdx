An **order** is the record of a single charge: the amounts, the tax, the invoice and the product and customer it belongs to. Polar creates one for every purchase, subscription start, renewal, charged plan change and [meter cycle](/features/usage-based-billing/billing#meter-cycle). See [Orders & subscriptions](/concepts/orders-and-subscriptions) for billing reasons and statuses.

The code examples use API version `2026-10` and the sandbox.

## Find an order

Orders are listed under **Sales** in the dashboard. Filter by customer, product, subscription, status or date.

<Tabs>
  <Tab title="Dashboard">
    - Open **Sales**
    - Select an order to see its amounts, customer, invoice and refunds
  </Tab>
  <Tab title="CLI">
    ```bash
    polar orders list --external-customer-id user_123 --status paid
    ```

    See [`polar orders`](/integrate/cli/reference/orders).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    List the paid orders for customer user_123 in my Polar sandbox.
    ```

    Uses the `orders_list` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
const orders = await polar.orders.list({
  external_customer_id: "user_123",
  status: "paid",
});
```

```python Python
orders = polar.orders.list(external_customer_id="user_123", status="paid")
```

```bash cURL
curl -G https://sandbox-api.polar.sh/v1/orders/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  --data-urlencode "external_customer_id=user_123" \
  --data-urlencode "status=paid"
```
</CodeGroup>

An order's `status` is `draft`, `pending`, `paid`, `refunded`, `partially_refunded` or `void`. Free orders, with a total of 0, are `paid` right away with no payment step.

## What's on an order

- **Amounts**: `subtotal_amount`, `discount_amount`, `net_amount`, `tax_amount` and `total_amount` in cents, with the `currency`.
- **Billing details**: `billing_name` and `billing_address`.
- **Tax**: the rate and amount collected. Polar handles the tax as your [Merchant of Record](/merchant-of-record/introduction).
- **Links** to the product, customer, discount and, for renewals, the subscription.
- **`billing_reason`**: why the order was created.
- **`custom_field_data`**: values from your [checkout fields](/features/custom-fields).
- **`metadata`**: your own key-value data.

## Edit billing details

You can change the billing name and address until the invoice is generated. Address fields used to calculate tax can't change.

```bash
polar orders update <order_id> --billing-name "Acme Inc."
```

Over the API, send `billing_name` or `billing_address` to [Update Order](/api-reference/current/orders/update-order).

## Invoices

Polar can produce a PDF invoice for every paid order. Generate it, then fetch its URL:

<CodeGroup>
```typescript TypeScript
await polar.orders.generateInvoice(orderId);
const invoice = await polar.orders.invoice(orderId);
console.log(invoice.url);
```

```python Python
polar.orders.generate_invoice(order_id)
invoice = polar.orders.invoice(order_id)
print(invoice.url)
```

```bash cURL
curl -X POST "https://sandbox-api.polar.sh/v1/orders/$ORDER_ID/invoice" \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10"

curl "https://sandbox-api.polar.sh/v1/orders/$ORDER_ID/invoice" \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10"
```
</CodeGroup>

From the CLI: `polar orders generate_invoice <order_id>`, then `polar orders invoice <order_id>`. In the dashboard, download it from the order page.

Generation returns `202 Accepted` and runs in the background. If the invoice isn't ready yet, retry the fetch shortly after. Check `is_invoice_generated` on the order.

<Note>
  Once an invoice is generated, its billing details are frozen. Customers can correct their name, company, tax ID or address from the [Customer Portal](/features/customer-portal/introduction), which regenerates the invoice.
</Note>

## Receipts

A **receipt** is the proof of payment for an order. Polar issues one for every paid order, numbered per customer as `RCPT-{customer-id}-{NNNN}`. It shows:

- The payment method (for example `Visa 4242`), the date paid and the amount.
- Any customer balance applied to the order.
- Any refunds, with dates and amounts.
- The same line items, taxes, totals and invoice number as the invoice.

Download it from the order page, with `polar orders receipt <order_id>`, or with [Get Order Receipt](/api-reference/current/orders/get-order-receipt). Customers get a **Download Receipt** button on each paid order in the Customer Portal.

The first request may return `202 Accepted` while the PDF renders. Retry shortly after to get a download URL.

## Export orders

Download orders as CSV from **Sales → Export CSV**, picking the columns to include. Over the API, call [Export Orders](/api-reference/current/orders/export-orders) with optional `product_id`, `status`, `created_after`, `created_before`, `timezone` and `columns` filters.

<Note>
  Export is dashboard or API only. Not available from the CLI or MCP server.
</Note>

## Payment attempts

Each attempt to charge an order is a **payment**, with a `status` of `pending`, `succeeded` or `failed`. A failed payment carries `decline_reason` and `decline_message`. Use it to see why a renewal failed.

```bash
polar payments list --order-id <order_id> --status failed
```

With an agent, use the `payments_list` and `payments_get` operations. See [List Payments](/api-reference/current/payments/list-payments).

When a renewal payment fails, Polar retries it on a schedule. Customers can also retry it themselves from the Customer Portal, up to 5 times. See [Failed payments](/features/subscriptions/failed-payments).

## Charge outside checkout

To charge a customer's saved payment method for a one-off amount, create a draft order and finalize it. See [Off-session charges](/features/off-session-charges).

## Refunds and disputes

Refund an order in full or in part from its page or the API. See [Refunds](/features/refunds). If a customer disputes the charge with their bank, see [Disputes](/features/disputes).

## Webhooks

| Event | When |
| --- | --- |
| `order.created` | An order is created. It may not be paid yet |
| `order.paid` | The order is paid. Most integrations act on this one |
| `order.updated` | The order changed, for example its status or billing details |
| `order.refunded` | A refund was issued on the order |

Check `billing_reason` to tell a purchase from a renewal. See [Webhook events](/integrate/webhooks/events).

## From the CLI or your agent

| Task | CLI | MCP operation |
| --- | --- | --- |
| List orders | `polar orders list` | `orders_list` |
| Get an order | `polar orders get <id>` | `orders_get` |
| Edit billing details | `polar orders update <id>` | `orders_update` |
| Generate an invoice | `polar orders generate_invoice <id>` | `orders_generate_invoice` |
| Get the invoice | `polar orders invoice <id>` | `orders_invoice` |
| Get the receipt | `polar orders receipt <id>` | `orders_receipt` |
| List payment attempts | `polar payments list --order-id <id>` | `payments_list` |

Creating, finalizing and exporting orders are API only.
