A **refund** returns money from a paid order to the customer. You can refund the full amount or part of it, from the dashboard, the CLI, your agent or the API. Each refund is its own object linked to the order.

The code examples use API version `2026-10` and the sandbox.

## What you can refund

You refund the **net amount**, excluding tax. The maximum is the order's net amount minus earlier refunds, taking any customer balance applied to the order into account (`refundable_amount` on the order). Polar refunds the matching tax automatically: all of it on a full refund, a proportional share on a partial one.

<Warning>
  **Payment fees aren't returned.** Card networks and payment processors charge for the transaction whether or not it's refunded later. You can refund the customer the full amount, but the fees stay deducted from your balance. See [Fees](/merchant-of-record/fees).
</Warning>

## Issue a refund

<Tabs>
  <Tab title="Dashboard">
    - Open the order under **Sales**
    - In the **Refunds** section, click **Refund order**
    - Set **Amount (excl. tax)**. It defaults to the maximum
    - Pick a **Reason**
    - For a one-time purchase, choose whether to **Revoke Benefits**
    - Click **Refund Order**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar refunds create --order-id <order_id> --reason customer_request \
      --amount 1500
    ```

    See [`polar refunds`](/integrate/cli/reference/refunds).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Refund $15 of order <order_id> in my Polar sandbox because the customer asked.
    ```

    Uses the `refunds_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
const refund = await polar.refunds.create({
  order_id: orderId,
  reason: "customer_request",
  amount: 1500,
  comment: "Customer asked within the trial week",
});
```

```python Python
refund = polar.refunds.create(
    order_id=order_id,
    reason="customer_request",
    amount=1500,
    comment="Customer asked within the trial week",
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/refunds/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "order_id": "'"$ORDER_ID"'",
    "reason": "customer_request",
    "amount": 1500,
    "comment": "Customer asked within the trial week"
  }'
```
</CodeGroup>

| Field | Description |
| --- | --- |
| `order_id` | The order to refund |
| `amount` | Net amount in cents, excluding tax. At least 1 |
| `reason` | See [Reasons](#reasons) |
| `comment` | An internal note. The customer doesn't see it |
| `revoke_benefits` | Revoke the order's benefits. Defaults to `false` in the API. The dashboard preselects it for one-time purchases |
| `metadata` | Your own key-value data |

## Reasons

| Value | Dashboard |
| --- | --- |
| `duplicate` | **Duplicate** |
| `fraudulent` | **Fraudulent** |
| `customer_request` | **Customer Request** |
| `service_disruption` | **Service Disruption** |
| `satisfaction_guarantee` | **Satisfaction Guarantee** |
| `other` | **Other** |

Refunds Polar issues itself use other reasons, such as `dispute_prevention`. You can't pick those.

## Revoking benefits

**One-time purchases.** Set `revoke_benefits` to remove the customer's access, such as license keys, file downloads or Discord and GitHub access.

**Subscriptions.** A refund can't revoke subscription benefits. The API returns an error if you try. Refunding returns money but doesn't end the subscription. To end access, [cancel or revoke the subscription](/features/subscriptions/manage). Polar revokes the benefits when it ends.

## Customer balance

A refund also reduces any positive balance the customer holds, by up to the refunded amount including tax. This is how you return a subscription [downgrade credit](/features/subscriptions/proration) to the card: downgrade credits go to the customer's balance, so refund the order they paid before the downgrade. That order can still be refunded after the downgrade.

Credit that isn't on the balance, such as a `prorate` credit waiting for the next invoice or balance already used by a later order, isn't taken back. Lower the refund by that amount so you don't pay it twice.

## When a refund is blocked

The API rejects a refund when:

- The order is already fully refunded.
- The order's payment is [disputed](/features/disputes). Handle the dispute instead.
- Refunds are blocked on the order or for your organization.
- You ask to revoke benefits on a subscription order.
- The payment processor already refunded the payment.

## Refunds issued by Polar

As your [Merchant of Record](/merchant-of-record/introduction), Polar can refund an order on your behalf to prevent a chargeback, even if your policy is "no refunds". Polar receives early warnings from the card networks before a dispute is filed and refunds some lower-value orders to stop it. The related subscription is canceled and the customer's benefits are revoked.

These refunds use the reason `dispute_prevention`. The matching [dispute](/features/disputes) shows as `prevented`. Keeping chargebacks low protects your account. See [Account reviews](/merchant-of-record/account-reviews).

| Event | When |
| --- | --- |
