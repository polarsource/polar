---

After a subscription starts, you can change what the customer pays for and when, or end it. Every change on this page is one call to [Update Subscription](/api-reference/current/subscriptions/update-subscription) (`PATCH /v1/subscriptions/{id}`), except revoking, which has its own endpoint.

Customers can make some of these changes themselves from the [Customer Portal](/features/customer-portal/introduction). See [What customers can do](#what-customers-can-do).

The code examples use the sandbox client from the [quickstart overview](/quickstart/overview#prerequisites), on API version `2026-10`. The cURL examples read the subscription ID from `$SUBSCRIPTION_ID`.

<Visibility for="agents">
  Use the sandbox until the user says otherwise. All changes are `PATCH /v1/subscriptions/{id}`; revoking is `DELETE /v1/subscriptions/{id}`. One PATCH body does one kind of change: product, proration, discount, `trial_end` and metadata together, or seats, units, billing period, cancel, revoke, pause, resume, or `pending_update: null`. `auto` proration needs API version 2027-01, which the MCP server uses but the CLI and the 2026-10 SDKs don't. Each change sends `subscription.updated`; ending one sends `subscription.canceled` or `subscription.revoked`.
</Visibility>

## Where to find each action in the dashboard

Open **Sales → Subscriptions** and select a subscription. Changes live in two places:

| Where | Action | Shown when |
| --- | --- | --- |
| **Update Subscription** → **Plan** | **New product**, **Proration behavior** and **Discount** | Always. **Proration behavior** shows when you pick a new product outside a trial |
| **Update Subscription** → **Trial** | **Trial End Date**, **Update trial end date**, **End trial now** | The subscription is **Trialing** |
| **Update Subscription** → **Billing Period** | **Billing Period End Date** | The subscription is **Active** |
| **Update Subscription** → **Seats** | **Total seats** and **Proration behavior** | The subscription is seat-based and **Active** or **Trialing** |
| Actions menu | **Cancel Subscription** or **Uncancel** | The subscription hasn't ended |
| Actions menu | **Pause Subscription**, **Cancel Scheduled Pause** or **Resume Now** | Active and not canceling, or paused |
| **Scheduled update** | **Cancel scheduled change** | A change is scheduled for the next cycle |

The **Plan** tab previews the charge or credit before you confirm. The subscription page also lists its orders, **Metadata** and **Activity**. Unit changes and metadata edits aren't in the dashboard. Use the CLI, an agent or the API.

## Change the plan

Move a subscription to another recurring product to upgrade or downgrade it.

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - Click **Update Subscription**
    - On the **Plan** tab, pick the **New product**
    - Choose a **Proration behavior**
    - Click **Update Subscription**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar subscriptions update $SUBSCRIPTION_ID \
      --product-id $PRODUCT_ID --proration-behavior prorate
    ```

    See [`polar subscriptions update`](/integrate/cli/reference/subscriptions#polar-subscriptions-update).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Move Jane's (jane@example.com) subscription to the Pro Yearly product in my Polar sandbox organization and prorate the difference on the next invoice.
    ```

    Uses the `subscriptions_list` and `subscriptions_update` operations of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
const subscription = await polar.subscriptions.update(subscriptionId, {
  product_id: productId,
  proration_behavior: "prorate",
});
```

```python Python
subscription = polar.subscriptions.update(
    subscription_id,
    product_id=product_id,
    proration_behavior="prorate",
)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/subscriptions/$SUBSCRIPTION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "product_id": "'"$PRODUCT_ID"'", "proration_behavior": "prorate" }'
```
</CodeGroup>

The [proration behavior](/features/subscriptions/proration) decides when the change applies and how the difference is billed. **Prorate & charge now** (`invoice`) and **Prorate on next invoice** (`prorate`) apply it now. **Charge full amount & reset cycle** (`reset`) also applies it now, but isn't available to every organization. **Schedule for next cycle** (`next_period`) schedules it for the next cycle. Leave it out to use your organization's default.

<Note>
  `auto` (prorate upgrades, schedule downgrades) is available from API version 2027-01. See [Update Subscription](/api-reference/next/subscriptions/update-subscription). The CLI and the `2026-10` SDKs don't accept it. Agents using the MCP server can, because it calls `2027-01`.
</Note>

The new product must:

- Exist in your organization and not be archived.
- Be recurring, with a price in the subscription's currency.
- Not use a pay-what-you-want (custom) price.

And the subscription must not be canceled, scheduled to cancel or `trial_ended`. Uncancel it first.

**Seat-based products.** You can move a non-seat subscription to a seat-based product: the customer becomes a `team` customer and takes a seat. That change must apply now, so `next_period` isn't allowed. You can't move a seat-based subscription back to a non-seat product.

**During a trial.** The trial carries over, with its end recalculated from the new product's trial length and the original `trial_start`. If the new product has no trial, or it would already be over, the trial ends and a paid cycle starts on the new product.

**Discounts carry over.** The current discount stays on the new product unless you also send `discount_id: null`.

## Change seats

Change how many seats a [seat-based subscription](/features/seat-based-pricing) pays for. Proration works like a plan change: `next_period` schedules the new count for the next cycle.

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - Click **Update Subscription**
    - On the **Seats** tab, set **Total seats**
    - Choose a **Proration behavior**
    - Click **Update Seats**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar subscriptions update $SUBSCRIPTION_ID --seats 25 --proration-behavior invoice
    ```
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Set Jane's (jane@example.com) team subscription to 25 seats and charge the difference now.
    ```

    Uses the `subscriptions_update` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.subscriptions.update(subscriptionId, {
  seats: 25,
  proration_behavior: "invoice",
});
```

```python Python
polar.subscriptions.update(subscription_id, seats=25, proration_behavior="invoice")
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/subscriptions/$SUBSCRIPTION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "seats": 25, "proration_behavior": "invoice" }'
```
</CodeGroup>

The count can't go below the price's minimum seats. Seat changes aren't allowed on a canceled, canceling or `trial_ended` subscription.

## Apply or remove a discount

Set `discount_id` to attach a [discount](/features/discounts), or to `null` to remove the current one. The change applies from the next billing cycle and doesn't re-bill the current period.

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - Click **Update Subscription**
    - On the **Plan** tab, pick a **Discount**, or clear the current one
    - Click **Update Subscription**
  </Tab>
  <Tab title="CLI">
    ```bash

    # Remove the discount
    polar subscriptions update $SUBSCRIPTION_ID --discount-id null
    ```
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Apply the LAUNCH20 discount to Jane's (jane@example.com) subscription.
    ```

    Uses the `discounts_list` and `subscriptions_update` operations of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.subscriptions.update(subscriptionId, { discount_id: discountId });
```

```python Python
polar.subscriptions.update(subscription_id, discount_id=discount_id)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/subscriptions/$SUBSCRIPTION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "discount_id": "'"$DISCOUNT_ID"'" }'
```
</CodeGroup>

Leaving `discount_id` out keeps the current discount, even when the same request changes the product.

<Note>
  From API version 2027-01, a discount removal scheduled with a `next_period` plan change shows as `pending_update.discount_unset: true`. There, `discount_id: null` on the pending update means the current discount stays.
</Note>

## Extend or end a trial

Set `trial_end` to a new date to extend a [trial](/features/subscriptions/trials), or to `"now"` to end it and charge the first cycle right away. If that charge fails, the subscription stays `trialing` with its original end date.

You can also start a trial on an `active` subscription through the CLI, an agent or the API. The new `trial_end` must be after the current period end. The subscription moves to `trialing` and the next charge moves to that date.

<Tabs>
  <Tab title="Dashboard">

  </Tab>

</Tabs>

## Pause and resume

Pausing stops billing without ending the subscription. The customer keeps the same subscription and payment method for when they come back.

### Pause at period end

Setting `pause_at_period_end` keeps the subscription `active`, with its benefits, until `current_period_end`. Then it moves to `paused`: benefits are revoked and no orders are created. Pausing never charges the customer and never takes effect mid-period.

Pass `resumes_at` to resume automatically on that date. It must be after the current period end. Leave it out to pause until you resume by hand.

You can only pause an `active` subscription that isn't set to cancel or already set to pause.

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - In the actions menu, click **Pause Subscription**
    - Optionally pick a **Resume date (optional)**
    - Click **Pause Subscription**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar subscriptions update $SUBSCRIPTION_ID \
      --pause-at-period-end --resumes-at 2027-03-01T00:00:00Z
    ```
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Pause Jane's (jane@example.com) subscription at the end of this period and resume it on March 1, 2027.
    ```

    Uses the `subscriptions_update` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.subscriptions.update(subscriptionId, {
  pause_at_period_end: true,
  resumes_at: "2027-03-01T00:00:00Z",
});
```

```python Python
polar.subscriptions.update(
    subscription_id,
    pause_at_period_end=True,
    resumes_at="2027-03-01T00:00:00Z",
)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/subscriptions/$SUBSCRIPTION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "pause_at_period_end": true, "resumes_at": "2027-03-01T00:00:00Z" }'
```
</CodeGroup>

To cancel a scheduled pause before it takes effect, set `pause_at_period_end` to `false`. In the dashboard, click **Cancel Scheduled Pause** in the actions menu. From the CLI, pass `--data '{"pause_at_period_end": false}'`.

## Cancel, uncancel or revoke

Both end the subscription. The difference is when.

- **Cancel at period end** keeps the subscription `active`, with its benefits, until `current_period_end`. No more renewals are created. You or the customer can uncancel until then.
- **Revoke** ends it now: the status moves to `canceled`, `ended_at` is set and benefits are revoked. It can't be undone.

### Cancel at period end

This is the option customers use from the [Customer Portal](/features/customer-portal/introduction).

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - In the actions menu, click **Cancel Subscription**
    - Set **Cancellation Date** to **End of current period**
    - Optionally set **Customer Feedback** and **Comment**
    - Click **Cancel Subscription**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar subscriptions update $SUBSCRIPTION_ID \
      --cancel-at-period-end --customer-cancellation-reason too_expensive
    ```
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Cancel Jane's (jane@example.com) subscription at the end of the current period. She said it's too expensive.
    ```

    Uses the `subscriptions_update` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.subscriptions.update(subscriptionId, {
  cancel_at_period_end: true,
  customer_cancellation_reason: "too_expensive",
});
```

```python Python
polar.subscriptions.update(
    subscription_id,
    cancel_at_period_end=True,
    customer_cancellation_reason="too_expensive",
)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/subscriptions/$SUBSCRIPTION_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "cancel_at_period_end": true, "customer_cancellation_reason": "too_expensive" }'
```
</CodeGroup>

`customer_cancellation_reason` is the **Customer Feedback** option in the dashboard. Add free text with `customer_cancellation_comment`, the **Comment** field.

| Dashboard | API `customer_cancellation_reason` |
| --- | --- |
| **Too Expensive** | `too_expensive` |
| **Missing Features** | `missing_features` |
| **Switched Service** | `switched_service` |
| **Unused** | `unused` |
| **Customer Service** | `customer_service` |
| **Low Quality** | `low_quality` |
| **Too Complicated** | `too_complex` |
| **Other** | `other` |

The same reasons make up the **Cancellations** charts under **Analytics → Metrics**.

<Warning>
  Only set the reason and comment when they come from the customer, for example from a cancellation survey or a support conversation. Customers can see `customer_cancellation_comment` in their purchase history, so don't put internal notes there.
</Warning>

### Uncancel

Reverse a cancellation at period end before the subscription ends. `cancel_at_period_end` is cleared, `ends_at` and `canceled_at` are unset, and the subscription renews as before. You can't uncancel a subscription that has ended.

### Revoke now

Use this when access must stop now: a terms-of-service violation, a chargeback, or a customer asking to stop immediately. Revoking doesn't refund anything. Issue a [refund](/features/refunds) separately if you need one.

<Warning>
  Revoking can't be undone. Cancel at period end if you might want to reverse it.
</Warning>

<Tabs>
  <Tab title="Dashboard">
    - Open the subscription
    - In the actions menu, click **Cancel Subscription**
    - Set **Cancellation Date** to **Immediately**
    - Click **Cancel Subscription**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar subscriptions revoke $SUBSCRIPTION_ID
    ```

    The CLI asks for confirmation. Pass `--confirm` to skip it in scripts.
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Revoke Jane's (jane@example.com) subscription now.
    ```

    Uses the `subscriptions_revoke` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.subscriptions.revoke(subscriptionId);
```

```python Python
polar.subscriptions.revoke(subscription_id)
```

```bash cURL

  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10"
```
</CodeGroup>

To record a cancellation reason when revoking, use `PATCH` with `{ "revoke": true, "customer_cancellation_reason": "..." }` instead.

## What customers can do

The [Customer Portal](/features/customer-portal/introduction) offers part of this page to customers. Some actions depend on your [portal settings](/features/customer-portal/settings) under **Settings → Customer Portal**:

| Action | Available |
| --- | --- |
| Cancel at period end and uncancel | Always |
| Update the payment method | Always |
| Change plan | With **Enable subscription plan changes**. Only to products with `public` visibility |
| Change seats | With **Enable subscription seat management** |
| Change units | With **Enable subscription unit changes** |
| Pause and resume | With **Enable subscription pausing** |
| Add billing details to a **Trial ended** subscription and restart it | Always. See [Trials](/features/subscriptions/trials#card-up-front-or-card-less) |
