A **trial** is a free period at the start of a subscription. The customer gets the product's benefits right away and is charged when the trial ends. The subscription is **Trialing** (`trialing`) until then. To see every trial, filter **Sales → Subscriptions** by the **Trialing** status.

The code examples use the sandbox client from the [quickstart overview](/quickstart/overview#prerequisites), on API version `2026-10`.

## Where a trial comes from

A trial has a length: a count and an interval of `day`, `week`, `month` or `year` (`trial_interval_count` and `trial_interval` in the API). You can set it in three places:

| Source | Set with |
| --- | --- |
| [Product](/features/products) | Dashboard, CLI, agent or API |
| [Checkout Link](/features/checkout/links) | Dashboard, CLI, agent or API |
| [Checkout Session](/features/checkout/session) | API |

A trial on a Checkout Link or Checkout Session **overrides the product's trial**. Set `allow_trial: false` on a Checkout Session to sell without a trial even when the product has one.

### Add a trial to a product

<Tabs>
  <Tab title="Dashboard">
    - Open **Catalog → Products** and edit a recurring product
    - Under **Free Trial Configuration**, click **Configure Trial**
    - Set **Trial duration**: a number and an interval
    - Leave **Require credit card up front** on, or turn it off for a card-less trial
    - Save the product
  </Tab>
  <Tab title="CLI">
    ```bash
    polar products update $PRODUCT_ID --trial-interval day --trial-interval-count 14
    ```

    The same flags work on `polar products create` and `polar checkout_links create|update`.
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Add a 14-day free trial to the Pro product in my Polar sandbox organization.
    ```

    Uses the `products_update` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

<CodeGroup>
```typescript TypeScript
await polar.products.update(productId, {
  trial_interval: "day",
  trial_interval_count: 14,
});
```

```python Python
polar.products.update(product_id, trial_interval="day", trial_interval_count=14)
```

```bash cURL
curl -X PATCH https://sandbox-api.polar.sh/v1/products/$PRODUCT_ID \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "trial_interval": "day", "trial_interval_count": 14 }'
```
</CodeGroup>

Set both fields to `null` to remove the trial.

### Set or skip a trial on a Checkout Session

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [productId],
  external_customer_id: "user_123",
  trial_interval: "week",
  trial_interval_count: 1,
});
```

```python Python
checkout = polar.checkouts.create(
    products=[product_id],
    external_customer_id="user_123",
    trial_interval="week",
    trial_interval_count=1,
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "products": ["'"$PRODUCT_ID"'"],
    "external_customer_id": "user_123",
    "trial_interval": "week",
    "trial_interval_count": 1
  }'
```
</CodeGroup>

Pass `allow_trial: false` instead to charge the customer today.

<Note>API only. Checkout Sessions can't be created from the CLI or MCP server.</Note>

## Card up front or card-less

By default, checkout collects a payment method for a trial without charging it. When the trial ends, Polar charges that payment method, the subscription becomes `active` and the customer gets the **Trial converted** email. If the charge fails, the usual [payment retries](/features/subscriptions/failed-payments) apply.

A **card-less trial** skips the payment form at checkout. Turn off **Require credit card up front** on the product or Checkout Link.

<Note>
  Available from API version 2027-01 as `trial_payment_setup_required: false` on products and Checkout Links. See [Update Product](/api-reference/next/products/update-product). In the dashboard, use the **Require credit card up front** switch.
</Note>

When a card-less trial ends without a payment method or a complete billing address:

1. The subscription moves to **Trial ended** (`trial_ended`) and the customer loses access to its benefits.
2. The customer can add their billing details in the [Customer Portal](/features/customer-portal/introduction). Polar charges them right away and the subscription becomes `active` with a new billing period.
3. If they don't, Polar revokes the subscription **14 days after the trial ended**. Usage recorded during the trial isn't billed.

Before the trial ends, the reminder email asks a customer without billing details to add them instead of announcing a charge. See [Reminders](#reminders).

A `trial_ended` subscription can't change plan, seats or units. Free products never move to `trial_ended`, since nothing is charged after the trial.

## Extend or end a trial

Set a new `trial_end` date to extend a trial, or `"now"` to end it and charge the first cycle right away. In the dashboard, open the subscription, click **Update Subscription** and use the **Trial** tab. It's only shown while the subscription is **Trialing**.

See [Extend or end a trial](/features/subscriptions/manage#extend-or-end-a-trial) for the CLI, prompt and API examples, including adding a trial to an `active` subscription.

## Reminders

Polar emails the customer before a trial ends, so the first charge isn't a surprise:

| Trial length | Reminder sent |
| --- | --- |
| 3 days or more | 3 days before the trial ends |
| 1 to 3 days | 1 day before the trial ends |
| Under 1 day | No reminder |

Fully free subscriptions and trials set to cancel at period end don't get a reminder. On a card-less trial without billing details, the same email asks the customer to add them.

Turn reminders off under **Settings → Customer Notifications → Trials → Trial conversion reminder**. The **Trial converted** email, sent when the first charge succeeds, is in the same group.

## Prevent trial abuse

Turn on **Settings → Subscriptions → Prevent trial abuse** to give each customer one trial across all your products. The API field is `subscription_settings.prevent_trial_abuse` on the organization.

Polar matches earlier trials on any of:

- **Email address**, normalized so aliases match: `jane+trial@example.com` counts as `jane@example.com`.
- **Payment method fingerprint**, so the same card is recognized under a different email.
- **Customer ID**, so a trial stays linked when the customer changes their email.

When a returning customer checks out, they see **No free trial for this purchase** and the checkout continues without the trial. They can still subscribe at the regular price.

Polar records every trial whether or not the setting is on, so trials started before you turn it on count too.

## From the CLI or your agent

| Task | CLI | MCP operation |
| --- | --- | --- |
| Add a trial to a product | `polar products update <id> --trial-interval day --trial-interval-count 14` | `products_update` |
| Add a trial to a Checkout Link | `polar checkout_links update <id> --trial-interval week --trial-interval-count 1` | `checkout_links_update` |
| List trialing subscriptions | `polar subscriptions list --status trialing` | `subscriptions_list` |
| Extend a trial | `polar subscriptions update <id> --trial-end 2026-12-15T00:00:00Z` | `subscriptions_update` |
| End a trial now | `polar subscriptions update <id> --trial-end now` | `subscriptions_update` |
