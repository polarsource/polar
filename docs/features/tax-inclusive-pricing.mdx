title: "Tax-inclusive pricing"
description: "Choose whether your prices include tax or have it added at checkout, for your organization or a single price."
---

**Tax behavior** decides whether the price you set already includes tax (inclusive) or has tax added on top at checkout (exclusive). It changes how a price is presented, not how much tax is owed.

## Tax behavior options

| Dashboard | API value | Effect |
| --- | --- | --- |
| **Location based** | `location` | Polar picks inclusive or exclusive from the customer's country. The default |
| **Inclusive** | `inclusive` | The price includes tax. Tax is taken out of the total at checkout |
| **Exclusive** | `exclusive` | The price is before tax. Tax is added on top at checkout |

With a 20% tax rate:

- **Inclusive:** a \$12.00 price costs the customer \$12.00, of which \$2.00 is tax and \$10.00 is net.
- **Exclusive:** a \$10.00 price costs the customer \$12.00: \$10.00 net plus \$2.00 tax.

Either way, the tax amount is itemized at checkout and on receipts.

## Location-based behavior

With **Location based**, Polar resolves the behavior at checkout from the customer's billing address. This follows regional conventions:

| Countries | Behavior |
| --- | --- |
| United States, Canada, India | Exclusive: tax is added on top |
| All other countries | Inclusive: tax is included in the price |

## Set the default

The default applies to every price that doesn't set its own.

- Open **Settings → Payments**
- Under **Default tax behavior**, choose **Location based**, **Inclusive** or **Exclusive**

Over the API, set `default_tax_behavior` with [Update Organization](/api-reference/current/organizations/update-organization).

<Note>
  Set it in the dashboard, through the API, or with `polar config apply` (`payments.tax` in your config file). The MCP server doesn't update organization settings.
</Note>

## Override a single price

A price can set its own `tax_behavior`, which wins over the default. The dashboard product form has no control for it, so set it through the API, CLI or your agent. All prices in the same currency on a product must use the same tax behavior.

<CodeGroup>
```typescript TypeScript
const product = await polar.products.create({
  name: "Pro",
  recurring_interval: "month",
  prices: [
    { amount_type: "fixed", price_amount: 2000, tax_behavior: "inclusive" },
  ],
});
```

```python Python
product = polar.products.create(
    name="Pro",
    recurring_interval="month",
    prices=[
        {"amount_type": "fixed", "price_amount": 2000, "tax_behavior": "inclusive"}
    ],
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/products/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Pro",
    "recurring_interval": "month",
    "prices": [{ "amount_type": "fixed", "price_amount": 2000, "tax_behavior": "inclusive" }]
  }'
```
</CodeGroup>

From the CLI, pass the same price JSON to `polar products create --prices` or `polar products update <id> --prices`. With an agent, the `products_create` and `products_update` operations take it too.

## Tax and the Merchant of Record

As your [Merchant of Record](/merchant-of-record/introduction), Polar calculates, collects and remits sales tax and VAT on every sale. Whatever the tax behavior, Polar:

- Calculates the tax for the customer's jurisdiction.
- Shows the tax breakdown at checkout.
- Issues a receipt that itemizes the tax.
- Remits the tax to the right authorities.

Changing the tax behavior doesn't change the tax rate or your obligations. It only changes whether the stated price includes tax.
