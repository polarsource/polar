description: "Send token usage for every LLM call, from the Vercel AI SDK in TypeScript or PydanticAI in Python, and create the meter that bills it."

To bill for LLM usage, send one event per model call with its token counts, and create a meter that sums them. This page shows both, plus how to record what each call cost you.

The examples use the sandbox and API version `2026-10`, with the sample customer `user_123` and the event name `ai_usage`. See [Usage](/concepts/usage) for how events and meters work.

## TypeScript: AI SDK

The LLM strategy from `@polar-sh/ingestion` wraps an [AI SDK](https://ai-sdk.dev) model. Every call through the wrapped model sends an event with its token usage. It works with AI SDK 5, 6 and 7, for `generateText`, `streamText` and anything else built on them.

```bash
pnpm add @polar-sh/ingestion ai @ai-sdk/openai
```

```typescript
import { Ingestion } from "@polar-sh/ingestion";
import { LLMStrategy } from "@polar-sh/ingestion/strategies/LLM";
import { openai } from "@ai-sdk/openai";
import { generateText } from "ai";

const llm = Ingestion({ accessToken: process.env.POLAR_ACCESS_TOKEN, server: "sandbox" })
  .strategy(new LLMStrategy(openai("gpt-4.1-nano")))
  .ingest("ai_usage");

export async function POST(request: Request) {
  const { prompt }: { prompt: string } = await request.json();

  const model = llm.client({ externalCustomerId: "user_123" });
  const { text } = await generateText({ model, prompt });

  return Response.json({ text });
}
```

Pass the user's ID from your session instead of `"user_123"`. With `streamText`, the event is sent when the stream finishes.

Each call sends its event in its own request. If sending fails, the strategy logs the error and your call still succeeds, but that event is lost.

Requires Node.js 24 or later. More strategies, for S3, streams and timings, are on [Ingestion strategies](/features/usage-based-billing/ingestion-strategies/ingestion-strategy).

### The event it sends

```json Event
{
  "name": "ai_usage",
  "external_customer_id": "user_123",
  "metadata": {
    "vendor": "openai.responses",
    "model": "gpt-4.1-nano",
    "inputTokens": 58,
    "cachedInputTokens": 0,
    "outputTokens": 19,
    "totalTokens": 77,
    "strategy": "LLM",
    "_llm": {
      "vendor": "openai.responses",
      "model": "gpt-4.1-nano",
      "input_tokens": 58,
      "cached_input_tokens": 0,
      "output_tokens": 19,
      "total_tokens": 77
    }
  }
}
```

`vendor` is the model's AI SDK provider ID. The `_llm` object is what Polar reads for the **By Model** and **By Vendor** views in [Cost insights](/features/cost-insights/introduction).

### Record the cost

Add `.cost()` to attach what each call cost you, in cents. It receives the token counts:

```typescript
const INPUT_CENTS_PER_TOKEN = 0.00001;
const OUTPUT_CENTS_PER_TOKEN = 0.00004;

const llm = Ingestion({ accessToken: process.env.POLAR_ACCESS_TOKEN, server: "sandbox" })
  .strategy(new LLMStrategy(openai("gpt-4.1-nano")))
  .cost((ctx) => ({
    amount: ctx.inputTokens * INPUT_CENTS_PER_TOKEN + ctx.outputTokens * OUTPUT_CENTS_PER_TOKEN,
    currency: "usd",
  }))
  .ingest("ai_usage");
```

Use your provider's current rates. The result is added to the event as `_cost`.

## Python: PydanticAI

There's no strategy package for Python. Read the usage from the run and send it with `polar.events.ingest`.

```bash
pip install polar-sdk pydantic-ai
```

```python
import os

from polar.v2026_10 import Polar
from pydantic_ai import Agent

polar = Polar(os.environ["POLAR_ACCESS_TOKEN"], environment="sandbox")
agent = Agent("openai:gpt-4.1-nano")


def answer(user_id: str, prompt: str) -> str:
    result = agent.run_sync(prompt)
    usage = result.usage

    polar.events.ingest(
        events=[
            {
                "name": "ai_usage",
                "external_customer_id": user_id,
                "metadata": {
                    "_llm": {
                        "vendor": "openai",
                        "model": "gpt-4.1-nano",
                        "input_tokens": usage.input_tokens,
                        "cached_input_tokens": usage.cache_read_tokens,
                        "output_tokens": usage.output_tokens,
                        "total_tokens": usage.total_tokens,
                    },
                },
            }
        ]
    )
    return result.output


print(answer("user_123", "Where is the windy city?"))
```

This sends one request per call. To send fewer requests, collect events and send them in batches. See [Send events in batches](/features/usage-based-billing/event-ingestion#send-events-in-batches).

This uses PydanticAI 2.x, where `result.usage` is a property. To record the cost, add `"_cost": {"amount": ..., "currency": "usd"}` next to `_llm`, with the amount in cents.

The same pattern works for any Python LLM client: read the token counts from its response and send them.

## Create the meter

Sum `_llm.total_tokens` across `ai_usage` events. The same meter works for events from both examples.

<Tabs>
  <Tab title="Dashboard">
    - Open **Products → Meters**
    - Click **Create Meter**
    - Set **Name** to "AI tokens"
    - Under **Filters**, add a condition: **Name** equals `ai_usage`
    - Set **Aggregation** to **Sum** over the property `_llm.total_tokens`
    - Set **Unit** to **Token**
    - Click **Create Meter**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar meters create --name "AI tokens" --unit token \
      --filter '{"conjunction":"and","clauses":[{"property":"name","operator":"eq","value":"ai_usage"}]}' \
      --aggregation '{"func":"sum","property":"_llm.total_tokens"}'
    ```
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a meter called "AI tokens" in my Polar sandbox organization that sums _llm.total_tokens across ai_usage events, with the token unit.
    ```

    Uses the `meters_create` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

To bill input and output tokens at different prices, create two meters, one summing `_llm.input_tokens` and one summing `_llm.output_tokens`, and add a metered price for each. See [Usage-based pricing](/features/usage-based-billing/billing).

## Check it worked

Make one call as `user_123`, then open **Products → Meters → AI tokens**. The call's tokens show on the **Overview** tab, and the event on the **Events** tab. Or run:

```bash
polar meters quantities <meter-id> --external-customer-id user_123 \
  --start-timestamp 2026-11-01T00:00:00Z --end-timestamp 2026-12-01T00:00:00Z --interval day
```

<Visibility for="agents">
  The TypeScript LLM strategy sends `_llm` in snake_case (`input_tokens`, `cached_input_tokens`, `output_tokens`, `total_tokens`) plus camelCase copies at the top level of `metadata`. Meter on `_llm.total_tokens` so TypeScript and Python events share one meter. Never pass `customerId: "xxx"` placeholders: use the app's user ID as `externalCustomerId`. Use the sandbox until the user says otherwise.
</Visibility>
