This guide calls the Polar API from Laravel with the `Http` client: it lists products, sends customers to checkout and handles webhooks. It uses API version `2026-10`. For a ready-made package with a `Billable` trait, Blade components and webhook handling, see the community-maintained [Laravel adapter](/integrate/sdk/adapters/laravel).

Build against the [sandbox](/integrate/sandbox) first. Nothing there moves real money. The complete code is in the [polar-laravel example](https://github.com/polarsource/polar-laravel) on GitHub.

## Set the access token

Create an [organization access token](/integrate/oat) in your sandbox organization, or run `polar auth token`, and add it to `.env`:

```bash .env
POLAR_ACCESS_TOKEN="polar_oat_..."
```

The examples call `https://sandbox-api.polar.sh`. When you go live, switch to `https://api.polar.sh` and a production token.

## List products

Add a route in `routes/web.php`:

```php
// routes/web.php
Route::get('/products', [ProductsController::class, 'handle']);
```

Then create `ProductsController` in `app/Http/Controllers`:

```php
// app/Http/Controllers/ProductsController.php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Http;

class ProductsController extends Controller
{
    public function handle(Request $request)
    {
        $data = Http::withToken(env('POLAR_ACCESS_TOKEN'))
            ->withHeaders(['Polar-Version' => '2026-10'])
            ->get('https://sandbox-api.polar.sh/v1/products/', [
                'is_archived' => 'false',
            ]);

        $products = $data->json();

        return view('products', ['products' => $products['items']]);
    }
}
```

Then create the `products` view in `resources/views`:

```php
// resources/views/products.blade.php
@foreach ($products as $product)
    <div>
        <h3>{{ $product['name'] }}</h3>
        <a href="/checkout?productId={{ $product['id'] }}">Buy</a>
    </div>
@endforeach
```

Each **Buy** link passes the product ID to `/checkout`, which you add next.

## Create a Checkout Session

This route creates a Checkout Session, redirects the customer to it, and sends them to a confirmation page after payment. Add it to `routes/web.php`:

```php
// routes/web.php
Route::get('/checkout', [CheckoutController::class, 'handle']);
```

Then create `CheckoutController` in `app/Http/Controllers`:

```php
// app/Http/Controllers/CheckoutController.php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Http;

class CheckoutController extends Controller
{
    public function handle(Request $request)
    {
        $productId = $request->query('productId', '');
        // Polar replaces {CHECKOUT_ID} with the checkout's ID
        $confirmationUrl = $request->getSchemeAndHttpHost() . '/confirmation?checkout_id={CHECKOUT_ID}';

        $result = Http::withToken(env('POLAR_ACCESS_TOKEN'))
            ->withHeaders(['Polar-Version' => '2026-10'])
            ->post('https://sandbox-api.polar.sh/v1/checkouts/', [
                'products' => [$productId],
                'success_url' => $confirmationUrl,
            ]);

        $data = $result->json();

        $checkoutUrl = $data['url'];

        return redirect($checkoutUrl);
    }
}
```

Link to `/checkout?productId=<product_id>`, as the products page does. After payment, Polar redirects the customer to the confirmation page. To link the Polar customer to your user, also send `external_customer_id` with your user's ID, so you can look them up by your own ID later.

## Show a confirmation page

Add the route to `routes/web.php`:

```php
// routes/web.php
Route::get('/confirmation', [ConfirmationController::class, 'handle']);
```

Then create `ConfirmationController` in `app/Http/Controllers`:

```php
// app/Http/Controllers/ConfirmationController.php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;

class ConfirmationController extends Controller
{
    public function handle(Request $request)
    {
        $data = Http::withToken(env('POLAR_ACCESS_TOKEN'))
            ->withHeaders(['Polar-Version' => '2026-10'])
            ->get('https://sandbox-api.polar.sh/v1/checkouts/' . $request->query('checkout_id'));

        $checkout = $data->json();

        Log::info(json_encode($checkout, JSON_PRETTY_PRINT));

        return view('confirmation', ['checkout' => $checkout]);
    }
}
```

The checkout isn't successful yet when the customer lands here. Its status is `confirmed` until the payment goes through and it becomes `succeeded`. Polar sends a `checkout.updated` webhook when that happens, so rely on webhooks, not this page, to grant access.

## Receive webhooks

Webhooks keep your database in sync with checkouts, orders and subscriptions.

### Forward webhooks locally

The [Polar CLI](/integrate/cli/webhooks) forwards your sandbox organization's webhooks to your local server. With `php artisan serve` on port 8000:

```bash Terminal
polar auth login --sandbox
polar webhook listen http://localhost:8000/api/webhook/polar
```

Copy the secret it prints into `.env`:

```bash .env
POLAR_WEBHOOK_SECRET="..."
```

When you deploy, [create a webhook endpoint](/integrate/webhooks/endpoints) for `https://<your-domain>/api/webhook/polar` and use that endpoint's secret instead. See [Webhook events](/integrate/webhooks/events) for the events you can subscribe to.

### Install the packages

Install the Standard Webhooks library, which verifies signatures:

```bash Terminal
composer require standard-webhooks/standard-webhooks:dev-main
```

Add the route to `routes/api.php`:

```php
// routes/api.php
Route::webhooks('/webhook/polar');
```

Make sure `bootstrap/app.php` loads `routes/api.php`:

```php
// bootstrap/app.php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        //
    })
    ->withExceptions(function (Exceptions $exceptions) {
        //
    })->create();
```

[Spatie's Webhook Client](https://github.com/spatie/laravel-webhook-client) receives the requests, calls your signature validator, stores each call and queues a job to process it:

```bash Terminal
composer require spatie/laravel-webhook-client
```

Publish its config:

```bash Terminal
php artisan vendor:publish --provider="Spatie\WebhookClient\WebhookClientServiceProvider" --tag="webhook-client-config"
```

This creates `config/webhook-client.php`. Point it at your secret, validator and job:

```php
// config/webhook-client.php
<?php
return [
    'configs' => [
        [
            /*
             * This package supports multiple webhook receiving endpoints. If you only have
             * one endpoint receiving webhooks, you can use 'default'.
             */
            'name' => 'default',

            /*
             * We expect that every webhook call will be signed using a secret. This secret
             * is used to verify that the payload has not been tampered with.
             */
            'signing_secret' => env('POLAR_WEBHOOK_SECRET'),

            /*
             * The name of the header containing the signature.
             */
            'signature_header_name' => 'webhook-signature',

            /*
             *  This class will verify that the content of the signature header is valid.
             *
             * It should implement \Spatie\WebhookClient\SignatureValidator\SignatureValidator
             */
            // 'signature_validator' => \Spatie\WebhookClient\SignatureValidator\DefaultSignatureValidator::class,
            'signature_validator' => App\Handler\PolarSignature::class,

            /*
             * This class determines if the webhook call should be stored and processed.
             */
            'webhook_profile' => \Spatie\WebhookClient\WebhookProfile\ProcessEverythingWebhookProfile::class,

            /*
             * This class determines the response on a valid webhook call.
             */
            'webhook_response' => \Spatie\WebhookClient\WebhookResponse\DefaultRespondsTo::class,

            /*
             * The classname of the model to be used to store webhook calls. The class should
             * be equal or extend Spatie\WebhookClient\Models\WebhookCall.
             */
            'webhook_model' => \Spatie\WebhookClient\Models\WebhookCall::class,

            /*
             * In this array, you can pass the headers that should be stored on
             * the webhook call model when a webhook comes in.
             *
             * To store all headers, set this value to `*`.
             */
            'store_headers' => [],

            /*
             * The class name of the job that will process the webhook request.
             *
             * This should be set to a class that extends \Spatie\WebhookClient\Jobs\ProcessWebhookJob.
             */
            'process_webhook_job' => App\Handler\ProcessWebhook::class,
        ],
    ],

    /*
     * The integer amount of days after which models should be deleted.
     *
     * 7 deletes all records after 1 week. Set to null if no models should be deleted.
     */
    'delete_after_days' => 30,
];
```
### Prepare the database

The client stores every webhook call in the database. Publish its migration:

```bash Terminal
php artisan vendor:publish --provider="Spatie\WebhookClient\WebhookClientServiceProvider" --tag="webhook-client-migrations"
```

Then run `php artisan migrate`.

### Set up the queue

Set `QUEUE_CONNECTION=database` in `.env`, or use another connection such as Redis. Create the jobs table with `php artisan queue:table`, then run `php artisan migrate`.

### Create the handlers

Create two files in `app/Handler`: `PolarSignature.php` and `ProcessWebhook.php`.

`PolarSignature` checks that the request came from Polar. It tries Standard Webhooks first, with the secret as-is, then Polar's original HMAC scheme, with the full `whsec_…` string base64-encoded. See [Custom validation](/integrate/webhooks/delivery#custom-validation).

```php
// app/Handler/PolarSignature.php
<?php

namespace App\Handler;

use Illuminate\Http\Request;
use Spatie\WebhookClient\WebhookConfig;
use Spatie\WebhookClient\SignatureValidator\SignatureValidator;

class PolarSignature implements SignatureValidator
{
    public function isValid(Request $request, WebhookConfig $config): bool
    {
        $headers = array(
            "webhook-id" => $request->header("webhook-id"),
            "webhook-signature" => $request->header("webhook-signature"),
            "webhook-timestamp" => $request->header("webhook-timestamp"),
        );
        $body = $request->getContent();
        $secret = $config->signingSecret;

        try {
            (new \StandardWebhooks\Webhook($secret))->verify($body, $headers);
            return true;
        } catch (\Throwable) {
            try {
                $legacySecret = base64_encode($secret);
                (new \StandardWebhooks\Webhook($legacySecret))->verify($body, $headers);
                return true;
            } catch (\Throwable) {
                return false;
            }
        }
    }
}
```

`ProcessWebhook` extends `ProcessWebhookJob`, which holds the stored webhook call:

```php
// app/Handler/ProcessWebhook.php
<?php

namespace App\Handler;

use Illuminate\Support\Facades\Log;
use Spatie\WebhookClient\Jobs\ProcessWebhookJob;

class ProcessWebhook extends ProcessWebhookJob
{
    public function handle()
    {
        $decoded = json_decode($this->webhookCall, true);
        $data = $decoded['payload'];

        switch ($data['type']) {
            case "checkout.created":
                // Handle the checkout created event
                break;
            case "checkout.updated":
                // Handle the checkout updated event
                break;
            case "subscription.created":
                // Handle the subscription created event
                break;
            case "subscription.updated":
                // Handle the subscription updated event
                break;
            case "subscription.active":
                // Handle the subscription active event
                break;
            case "subscription.revoked":
                // Handle the subscription revoked event
                break;
            case "subscription.canceled":
                // Handle the subscription canceled event
                break;
            default:
                // Handle unknown event
                Log::info($data['type']);
                break;
        }

        //Acknowledge you received the response
        http_response_code(200);
    }
}
```

Run `php artisan queue:listen` to process the jobs.

### Track subscriptions

- Grant access on `subscription.active` and remove it on `subscription.revoked`.
- `subscription.canceled` doesn't end access. A customer who cancels usually keeps access until the end of the billing period, when Polar sends `subscription.revoked`.

To handle access in one place instead, listen to `customer.state_changed`. See [Customer state](/integrate/customer-state).
