This guide adds Polar to a Next.js App Router project: a client for the API, a route that sends customers to checkout, and a route that receives webhooks. It uses the [`@polar-sh/nextjs` adapter](/integrate/sdk/adapters/nextjs) and API version `2026-10`.

Build against the [sandbox](/integrate/sandbox) first. Nothing there moves real money. The complete code is in the [polar-next example](https://github.com/polarsource/polar-next) on GitHub.

To scaffold the routes in an existing Next.js project instead, run:

```bash Terminal
npx polar-init
```

## Install the packages

```bash Terminal
pnpm add @polar-sh/sdk @polar-sh/nextjs
```

## Set the access token

Create an [organization access token](/integrate/oat) in your sandbox organization, or run `polar auth token`, and add it to `.env.local`:

```bash .env.local
POLAR_ACCESS_TOKEN="polar_oat_..."
```

## Create an API client

Use the client for any API call your app makes, such as listing products:

```typescript src/polar.ts
import { createPolar } from "@polar-sh/sdk/2026-10";

export const polar = createPolar({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  environment: "sandbox",
});
```

When you go live, remove `environment` or set it to `"production"`, and use a production token.

## Add a checkout route

The `Checkout` handler creates a Checkout Session and redirects the customer to it:

```typescript src/app/checkout/route.ts
import { Checkout } from "@polar-sh/nextjs";

export const GET = Checkout({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  successUrl: "https://example.com/confirmation",
  environment: "sandbox",
});
```

Link to `/checkout?products=<product_id>`. Add `&external_customer_id=<your user ID>` so Polar links the customer to your user. The handler appends `checkout_id={CHECKOUT_ID}` to `successUrl`. See the [adapter reference](/integrate/sdk/adapters/nextjs#checkout) for every query parameter.

## Receive webhooks

Webhooks keep your database in sync with checkouts, orders and subscriptions.

### Forward webhooks locally

The [Polar CLI](/integrate/cli/webhooks) forwards your sandbox organization's webhooks to your dev server:

```bash Terminal
polar auth login --sandbox
polar webhook listen http://localhost:3000/api/webhook/polar
```

Copy the secret it prints into `.env.local`:

```bash .env.local
POLAR_WEBHOOK_SECRET="..."
```

When you deploy, [create a webhook endpoint](/integrate/webhooks/endpoints) for `https://<your-domain>/api/webhook/polar` and use that endpoint's secret instead.

### Add the webhook route

The `Webhooks` handler verifies the signature, then calls your handlers with a typed payload:

```typescript src/app/api/webhook/polar/route.ts
import { Webhooks } from "@polar-sh/nextjs";

export const POST = Webhooks({
  webhookSecret: process.env.POLAR_WEBHOOK_SECRET!,
  onOrderPaid: async (payload) => {
    // Fulfill the order in payload.data
  },
  onCustomerStateChanged: async (payload) => {
    // Grant or revoke access from payload.data
  },
});
```

`onCustomerStateChanged` is often all you need for access control. See [Customer state](/integrate/customer-state) and [Webhook events](/integrate/webhooks/events).

## Check it worked

- Start your dev server and `polar webhook listen`
- Open `/checkout?products=<product_id>` and pay with the test card `4242 4242 4242 4242`
- You land on your success URL, and the CLI logs `order.paid` and `customer.state_changed` deliveries to your route

The checkout's status reaches `succeeded` shortly after payment. Polar sends `checkout.updated` when it does, so a confirmation page that waits for it can update its UI then.
