Every Polar API request carries a bearer token in the `Authorization` header. Which token you use depends on whose data you're acting on.

| Token | Prefix | Use it when |
| --- | --- | --- |
| [Organization access token](/integrate/oat) (OAT) | `polar_oat_` | Your server, scripts or CI call the API for your own organization. Use this in almost every integration. |
| [OAuth 2.0 access token](/integrate/oauth2/introduction) | `polar_at_u_` | You build an app or service that acts on behalf of other Polar users. |
| [Customer session token](/features/customer-portal/custom-portal) | `polar_cst_` | One of your customers calls the Customer Portal API from your app. |

<Warning>
  A token can act on your organization's data within its scopes. Keep tokens on your server or in a secret store. Never put them in client-side code or commit them.
</Warning>

## Send a token

Pass the token as a bearer token. The SDKs do this for you:

<CodeGroup>
```typescript TypeScript
import { createPolar } from "@polar-sh/sdk/2026-10";

const polar = createPolar({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  environment: "sandbox",
});
```

```python Python
import os

from polar.v2026_10 import Polar

polar = Polar(os.environ["POLAR_ACCESS_TOKEN"], environment="sandbox")
```

```bash cURL
curl https://sandbox-api.polar.sh/v1/products/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10"
```
</CodeGroup>

Tokens belong to one environment. A sandbox token only works against `https://sandbox-api.polar.sh`, and a production token only against `https://api.polar.sh`. See [Sandbox](/integrate/sandbox).

To create an organization access token from the terminal, run `polar auth token`. See [Access tokens](/integrate/oat#create-a-token).

<Visibility for="agents">
  Use an organization access token unless the user is building an app for other Polar users. Never put a token in browser or mobile code. Read it from `POLAR_ACCESS_TOKEN` on the server.
</Visibility>

## Leaked tokens

Polar is part of the [GitHub Secret Scanning Program](https://docs.github.com/en/code-security/secret-scanning/about-secret-scanning). When GitHub finds a Polar token in a public repository or discussion, Polar is notified and revokes the token immediately.

If you received an email about a leaked token, that's what happened. The email says which token leaked and where it was found. Create a new token, update your application and check the source of the leak. The [OWASP Secrets Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) covers good practices for storing secrets.
