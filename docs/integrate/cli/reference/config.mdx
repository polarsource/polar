## polar config init

Create a billing config file from your organization's meters, benefits and products, and show what to do next

```bash
polar config init [flags] [<file>]
```

**Arguments**

| Argument | Type | Description |
| --- | --- | --- |
| `file` | `string` | Where to write the config. Defaults to polar.config.ts at the root of a JavaScript or TypeScript project, polar.config.json otherwise (optional) |

**Flags**

| Flag | Type | Description |
| --- | --- | --- |
| `--org` | `string` | Organization ID or slug for this invocation only |
| `--sandbox` | `boolean` | Use the sandbox environment |
| `--production` | `boolean` | Use the production environment |
| `--format` | `choice` | Write TypeScript (ts) or JSON (json). Detected from your project when omitted: ts with a package.json. In a terminal you confirm it, or choose when there is none. Outside a terminal it writes json when there is none (choices: ts, json) |
| `--skip-install` | `boolean` | Do not install the package a TypeScript config imports, @polar-sh/config |
| `--confirm`, `-c` | `boolean` | Use the suggested external IDs for meters, benefits and products that have none, without asking |
| `--external-id` | `string` | Give the resource with this ID this external ID, as &lt;id&gt;=&lt;external ID&gt;. Repeat it for each resource. Without a terminal, every resource without an external ID needs one, unless you pass --confirm |

**Examples**

Write a config for the active organization at the root of your project
```bash
polar config init
```

Set up your sandbox organization, logging in first if needed
```bash
polar config init --sandbox
```

Write a JSON config for another organization
```bash
polar config init --org acme --format json
```

Use the suggested external IDs for existing resources that have none, for scripts and agents
```bash
polar config init --json --confirm
```

Choose the external ID of an existing resource; init --json lists the IDs that need one
```bash
polar config init --json --external-id <id>=pro
```

Write to a specific path and print the result as JSON, for scripts and agents
```bash
polar config init billing/polar.config.ts --json
```

## polar config draft

Save a billing config file to the draft catalog of your organization. Nothing changes for customers until you publish it

```bash

```

**Arguments**

| Argument | Type | Description |
| --- | --- | --- |
| `file` | `string` | Path to the billing config file. Defaults to the first of polar.config.ts, polar.config.mts, polar.config.cts, polar.config.js, polar.config.mjs, polar.config.cjs, polar.config.json, polar.json found in the current directory (optional) |

**Flags**

| Flag | Type | Description |
| --- | --- | --- |
| `--org` | `string` | Organization ID or slug for this invocation only |
| `--confirm`, `-c`, `--aladåb` | `boolean` | Skip the confirmation prompt |
| `--name` | `string` | Name of the draft catalog version. Defaults to v&#123;n&#125; when published |
| `--force` | `boolean` | Save even when the draft on Polar has changes that are not in the file, discarding them |

**Examples**

```bash

```

Save a specific file
```bash

```

```bash

```

```bash
polar config draft --confirm
```

Name the draft catalog version
```bash

```

Save the file even when the draft has changes that are not in it
```bash
polar config draft --force
```

Print what was saved as JSON, for scripts and agents

## polar config generate

Write the names in a billing config (its meters, benefits, products and the events its meters count) to a file your application code imports. A misspelled name then fails in your type checker instead of at run time

```bash
polar config generate [flags] [<file>]
```

**Arguments**

| Argument | Type | Description |
| --- | --- | --- |
| `file` | `string` | Path to the billing config file. Defaults to the first of polar.config.ts, polar.config.mts, polar.config.cts, polar.config.js, polar.config.mjs, polar.config.cjs, polar.config.json, polar.json found in the current directory (optional) |

**Flags**

| Flag | Type | Description |
| --- | --- | --- |
| `--language` | `choice` | The language to generate: Python (py). When omitted it follows the file name given to --out, then the nearest project at or above the config or the current directory (choices: py) |
| `--out` | `string` | Where to write the file. Defaults to polar_types.py next to the config. A file this command did not write is never replaced |
| `--check` | `boolean` | Write nothing, and fail when the generated file is missing or out of date |

**Examples**

Write the names next to the config, in the language of the project
```bash
polar config generate
```

Choose where the file goes
```bash
polar config generate --out app/polar_types.py
```

Fail in CI when the generated file is out of date
```bash
polar config generate --check
```

Print what was written as JSON, for scripts and agents
```bash
polar config generate --json
```
