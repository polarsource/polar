Use Polar's remote Model Context Protocol (MCP) server to give AI agents secure access to your Polar organization. Agents can look up data and take actions across your products, customers, subscriptions, orders, benefits, and more.

<Info>
  Polar MCP uses OAuth. When you connect a client, your browser opens so you can sign in and authorize access to your organization. You never need to copy an API key into your agent.
</Info>

## Choose an environment

Use the production server for your live organization and the sandbox server while building or testing.

| Environment | Server URL |
| --- | --- |
| Production | `https://mcp.polar.sh/mcp/polar-mcp` |
| Sandbox | `https://mcp.polar.sh/mcp/polar-sandbox` |

## Connect your agent

Choose your client and add the production server. To connect to the sandbox instead, replace the production URL with `https://mcp.polar.sh/mcp/polar-sandbox` and use a distinct name such as `polar-sandbox`.

<Tabs>
  <Tab title="Cursor">
    Add the following to `.cursor/mcp.json` in your project, or to `~/.cursor/mcp.json` to make Polar available in every project:

    ```json
    {
      "mcpServers": {
        "polar": {
          "url": "https://mcp.polar.sh/mcp/polar-mcp"
        }
      }
    }
    ```

    Open Cursor's MCP settings and connect to `polar` to complete authorization.
  </Tab>

  <Tab title="Claude Code">
    Run:

    ```bash
    claude mcp add --transport http polar https://mcp.polar.sh/mcp/polar-mcp
    ```

    Then open `/mcp` in Claude Code and authenticate `polar` with OAuth.
  </Tab>

  <Tab title="ChatGPT">
    In ChatGPT, open **Settings** → **Connectors**, enable developer mode if prompted, and add a custom connector with:

    - **Name:** `Polar`
    - **MCP server URL:** `https://mcp.polar.sh/mcp/polar-mcp`

    Save the connector, select **Connect**, and complete authorization in the browser.
  </Tab>

  <Tab title="Claude Desktop">
    Open **Settings** → **Connectors**, select **Add custom connector**, and enter:

    - **Name:** `Polar`
    - **MCP server URL:** `https://mcp.polar.sh/mcp/polar-mcp`

    Save the connector, select **Connect**, and complete authorization in the browser.
  </Tab>

  <Tab title="Codex">
    Add the following to `~/.codex/config.toml`, or to `.codex/config.toml` for a trusted project:

    ```toml
    [mcp_servers.polar]
    url = "https://mcp.polar.sh/mcp/polar-mcp"
    ```

    Then authenticate with OAuth:

    ```bash
    codex mcp login polar
    ```

    Use `/mcp` in Codex to confirm that the server is connected.
  </Tab>

  <Tab title="OpenCode">
    Add the following to `opencode.jsonc`:

    ```jsonc
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "polar": {
          "type": "remote",
          "url": "https://mcp.polar.sh/mcp/polar-mcp"
        }
      }
    }
    ```

    OpenCode will ask you to authorize Polar when it first connects.
  </Tab>

  <Tab title="Other clients">
    If your client accepts a remote MCP URL, add:

    ```text
    https://mcp.polar.sh/mcp/polar-mcp
    ```

    If it only supports local commands, use the `mcp-remote` bridge:

    ```json
    {
      "mcpServers": {
        "polar": {
          "command": "npx",
          "args": [
            "mcp-remote",
            "https://mcp.polar.sh/mcp/polar-mcp"
          ]
        }
      }
    }
    ```
  </Tab>
</Tabs>

## How dynamic toolsets work

Polar supports a broad set of operations. Sending every operation and its full input schema to an agent at the start of every conversation would consume context, make tool selection less reliable, and add unnecessary latency.

Instead, Polar uses a dynamic toolset with three lightweight meta-tools. Your agent discovers the relevant operation at runtime, loads only the schema it needs, and then executes it.

| Tool | What it does |
| --- | --- |
| `search_tools` | Searches the Polar operation catalog and returns the tools relevant to the agent's task. |
| `describe_tools` | Loads the description and input schema for selected tools before the agent calls them. |
| `execute_tool` | Runs a selected tool with the supplied arguments and returns the result. |

<Steps>
  <Step title="Search">
    The agent calls `search_tools` with what it wants to accomplish, such as “find a customer and check their active subscriptions.”
  </Step>
  <Step title="Inspect">
    The agent calls `describe_tools` for the best matches to learn their exact inputs and behavior.
  </Step>
  <Step title="Execute">
    The agent calls `execute_tool` with the selected tool name and validated arguments.
  </Step>
</Steps>
