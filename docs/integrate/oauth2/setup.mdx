An **OAuth 2.0 client** identifies your app to Polar and to the users who connect it. Create one before you [connect users](/integrate/oauth2/connect).

Clients belong to your user account, not to an organization. Create a separate client in the [sandbox](/integrate/sandbox) for development.

## Create a client

- Open [**Account Settings → OAuth Apps**](https://polar.sh/dashboard/account/developer)
- Click **Create OAuth App**
- Fill in the fields below
- Click **Create**

| Field | Description |
| --- | --- |
| **Application Name** | Shown to users on the consent screen. |
| **Client Type** | **Confidential Client** for apps with a server that can keep a secret. **Public Client** for single-page, mobile and desktop apps. See [Public clients](/integrate/oauth2/connect#public-clients). |
| **Redirect URIs** | Where Polar sends users after they approve access. Must use `https://`, except on `localhost`, so `http://localhost` works during development. |
| **Scopes** | The scopes your app may request. Select only the ones it needs. |
| **Homepage URL** | Your app's URL, shown on the consent screen. |
| **Terms of Service**, **Privacy Policy** | Optional links, shown on the consent screen. |

<Note>Dashboard or API only. Not available from the CLI or MCP server.</Note>

You can also register clients from code with [Create Client](/api-reference/current/oauth2/create-client), which follows the OAuth 2.0 Dynamic Client Registration standard.

## Store the credentials

After you create the client, Polar shows its **Client ID** (`polar_ci_…`) and **Client Secret** (`polar_cs_…`).

To find them later, open the app in **Account Settings → OAuth Apps** and click **Reveal client secret**. The same page lets you edit the client's fields or delete it.

<Warning>
  The Client Secret lets anyone request tokens as your app. Keep it on your server, never in a browser or mobile app, and never commit it. A public client has no secret to protect, which is why it must use PKCE.
</Warning>
