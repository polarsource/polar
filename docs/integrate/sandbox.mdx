The **sandbox** is a separate Polar environment for building and testing. It has its own dashboard at [sandbox.polar.sh](https://sandbox.polar.sh/start), its own API at `https://sandbox-api.polar.sh`, and its own accounts, organizations, products, customers and access tokens. Nothing in it moves real money.

<Note>
  **Why a separate environment instead of a test mode?** As the Merchant of Record, Polar tracks every money movement. Keeping test data in a separate environment means it can never mix with live data. It also lets you create as many organizations as you need to test different setups.
</Note>

## Get started

Open [sandbox.polar.sh](https://sandbox.polar.sh/start), or select **Go to sandbox** in the organization switcher of the dashboard. Create a user account and an organization there, separate from your production ones. Then follow the [quickstart](/quickstart/overview).

## Test payments

The sandbox runs the full customer flow, including checkout. Pay with Stripe's [test card numbers](https://docs.stripe.com/testing#cards). For a successful payment, use this card with any future expiration date and any CVC:

```text
4242 4242 4242 4242
```

## API and SDK

Send requests to `https://sandbox-api.polar.sh` instead of `https://api.polar.sh`, with an [access token](/integrate/oat) created in the sandbox. Production tokens don't work in the sandbox, and sandbox tokens don't work in production.

The SDKs take an `environment` option:

<CodeGroup>
```typescript TypeScript
import { createPolar } from "@polar-sh/sdk/2026-10";

const polar = createPolar({
  accessToken: process.env.POLAR_ACCESS_TOKEN!,
  environment: "sandbox",
});
```

```python Python
import os

from polar.v2026_10 import Polar

polar = Polar(
    os.environ["POLAR_ACCESS_TOKEN"],
    environment="sandbox",
)
```

```bash cURL
curl https://sandbox-api.polar.sh/v1/products/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10"
```
</CodeGroup>

See the [API reference](/api-reference/current/introduction) for every endpoint.

## CLI

Sign in to the sandbox and choose a sandbox organization. Commands then talk to the sandbox:

```bash Terminal
polar auth login --sandbox
polar auth org
```

The active organization decides the environment, and you can be signed in to sandbox and production at once. With an access token instead of a session, set `POLAR_ENVIRONMENT=sandbox`. See [CLI authentication](/integrate/cli/authentication).

## MCP server

Connect your agent to the sandbox server, `https://mcp.polar.sh/mcp/polar-sandbox`, next to the production one. Prompts that say "in my Polar sandbox" use it. See [MCP server](/integrate/mcp).

<Visibility for="agents">
  Default to the sandbox: `https://sandbox-api.polar.sh`, `environment: "sandbox"`, `polar auth login --sandbox` and the `polar-sandbox` MCP server. Switch to production only when the user asks.
</Visibility>

## Limitations

These apply only to the sandbox:

- Customer-facing emails, such as order confirmations and renewal reminders, are only delivered to members of your organization. Manage them in [**Settings → Members**](https://polar.sh/to/dashboard/settings/members). Sub-addressing aliases like `you+test@example.com` work.
