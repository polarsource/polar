Once you've [set up an endpoint](/integrate/webhooks/endpoints), Polar sends it a signed `POST` request for each event. Your handler verifies the signature, parses the payload and returns a `2xx` status. Anything else counts as a failed delivery, and Polar retries it.

The examples use API version `2026-10`. The endpoint's API version must match the version of your SDK import, so the SDK can parse the payloads.

## Validate and parse webhooks

The TypeScript and Python SDKs verify the signature and return a typed event in one call. Pass the **raw** request body: if your framework has already parsed the JSON, the signature won't match.

<CodeGroup>
```typescript TypeScript
import express, { NextFunction, Request, Response } from "express";
import { webhooks } from "@polar-sh/sdk/2026-10";

const app = express();

app.post(
  "/api/webhooks",
  express.raw({ type: "application/json" }),
  async (req: Request, res: Response, next: NextFunction) => {
    try {
      const event = await webhooks.validateEvent(
        req.body,
        {
          "webhook-id": req.header("webhook-id") ?? "",
          "webhook-timestamp": req.header("webhook-timestamp") ?? "",
          "webhook-signature": req.header("webhook-signature") ?? "",
        },
        process.env.POLAR_WEBHOOK_SECRET!,
      );

      if (event.type === "order.paid") {
        // Queue the work and return quickly
      }

      res.status(202).send("");
    } catch (error) {
      if (error instanceof webhooks.PolarWebhookVerificationError) {
        res.status(403).send("");
        return;
      }
      if (error instanceof webhooks.PolarWebhookUnknownTypeError) {
        res.status(202).send("");
        return;
      }
      next(error);
    }
  },
);
```

```python Python
import os

from flask import Flask, request
from polar.v2026_10.webhooks import (
    PolarWebhookUnknownTypeError,
    PolarWebhookVerificationError,
    validate_event,
)

app = Flask(__name__)


@app.post("/api/webhooks")
def webhook():
    try:
        event = validate_event(
            request.get_data(),
            dict(request.headers),
            os.environ["POLAR_WEBHOOK_SECRET"],
        )
    except PolarWebhookVerificationError:
        return "", 403
    except PolarWebhookUnknownTypeError:
        return "", 202

    if event.type == "order.paid":
        # Queue the work and return quickly
        ...

    return "", 202
```
</CodeGroup>

`POLAR_WEBHOOK_SECRET` is the secret from the endpoint page in the dashboard, or the one `polar webhook listen` prints while you develop.

| Error | Meaning | Respond with |
| --- | --- | --- |
| `PolarWebhookVerificationError` | Missing headers, a bad signature, or a timestamp more than 5 minutes from your server's clock | `403` |
| `PolarWebhookUnknownTypeError` | An event type that your SDK version doesn't know yet | `202`, so Polar doesn't retry it |
| `PolarWebhookError` | The body isn't a valid payload | `400` |

Using Next.js, Nuxt, TanStack Start or Better Auth? A [framework adapter](/integrate/sdk/adapters/introduction) gives you this handler in a few lines.

<Visibility for="agents">
  Always verify the signature before acting on a payload, using the raw body. Return `403` on `PolarWebhookVerificationError` and `202` on `PolarWebhookUnknownTypeError`. Make handlers idempotent on the `webhook-id` header, since retries and redeliveries reuse it. Pin the SDK import (`@polar-sh/sdk/2026-10`, `polar.v2026_10`) to the endpoint's API version.
</Visibility>

### Custom validation

Without an SDK, use a [Standard Webhooks library](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries) or follow the [specification](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md). Each request has these headers:

| Header | Content |
| --- | --- |
| `webhook-id` | The event ID. The same on every retry and redelivery, so use it to deduplicate. |
| `webhook-timestamp` | Unix timestamp of this attempt, in seconds |
| `webhook-signature` | `v1,` followed by the base64 HMAC-SHA256 of `{webhook-id}.{webhook-timestamp}.{body}` |
| `webhook-api-version` | The endpoint's API version, such as `2026-10` |

The HMAC key depends on when the endpoint's secret was generated:

- **On or after 8 September 2026, 00:00 UTC:** Standard Webhooks. Pass the `whsec_…` secret to the library as-is.
- **Before that:** Polar's original HMAC. The key is the UTF-8 bytes of the full `whsec_…` string. Base64-encode that string before you pass it to a Standard Webhooks library.

The endpoint page in the dashboard shows which scheme applies. Polar SDKs 1.0.0-alpha.19 and later try both keys, so you only pass the `whsec_…` secret.

## Retries and timeouts

A delivery succeeds when your endpoint returns a `2xx` status within **10 seconds**. Everything else fails: other status codes, timeouts, network and TLS errors, and redirects. Polar doesn't follow redirects.

A failed delivery is retried with exponential backoff, up to 20 minutes between attempts, for **10 attempts** in total. An event fails when all 10 attempts fail.

Respond as fast as you can. Verify the signature, store or queue the payload, return `202`, and do the work in a background job.

Polar holds an event briefly while earlier events for the same endpoint are still pending, so events usually arrive in the order they happened. Order isn't guaranteed. Read timestamps and statuses from the payload rather than relying on arrival order, and handle the same event more than once safely.

### Endpoint disabling

Polar disables an endpoint after **10 consecutive failed events**. A delivery that fails and then succeeds on retry doesn't count. When that happens:

- The endpoint stops receiving new events.
- Events still waiting to be delivered are skipped.
- Every member of the organization gets an email.

Fix the endpoint first, then turn it back on:

- Open [**Settings → Webhooks**](https://polar.sh/to/dashboard/settings/webhooks) and select the endpoint
- Switch it from **Disabled** to **Enabled**

Or run `polar webhooks update_webhook_endpoint <id> --enabled=true`. To catch up on what you missed, [redeliver](#redeliver-an-event) the skipped events.

## Monitor deliveries

Each endpoint's page in **Settings → Webhooks** has a **Deliveries** log with every attempt: its **ID**, **Status** (the HTTP code, or **Failed**), event **Type** and **Sent At**. Filter by status, event type, HTTP response class (2xx to 5xx) or date range, or search.

Select a delivery to see:

- **Event ID**, **Event Timestamp** and **Event API Version**
- **Delivery ID** and **Sent at**
- The **Payload** Polar sent, with **Copy payload**
- The **Response** your endpoint returned, up to 2,048 characters

Polar keeps payloads and responses for 90 days. After that the event shows as **Archived event** and can't be redelivered.

From code, list deliveries with [`List Webhook Deliveries`](/api-reference/current/webhooks/list-webhook-deliveries), `polar webhooks list_webhook_deliveries --endpoint-id <id> --succeeded=false`, or the `webhooks_list_webhook_deliveries` MCP operation.

### Redeliver an event

Redelivery sends the same event again with the same `webhook-id`, whether the earlier attempts failed or succeeded.

<Tabs>
  <Tab title="Dashboard">
    - Open the endpoint in **Settings → Webhooks**
    - Select the delivery in **Deliveries**
    - Click **Redeliver**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar webhooks redeliver_webhook_event <event_id>
    ```

    Take the event ID from `webhook_event.id` in `polar webhooks list_webhook_deliveries`. See [`polar webhooks`](/integrate/cli/reference/webhooks#polar-webhooks-redeliver_webhook_event).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Find the failed webhook deliveries to my Polar sandbox endpoint from the last day and redeliver them.
    ```

    Uses the `webhooks_list_webhook_deliveries` and `webhooks_redeliver_webhook_event` operations of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

## Troubleshooting

### Not receiving webhooks

Deliveries show up in the log but never reach your handler? Check the HTTP status in the **Deliveries** log.

**No status or a timeout**

- Developing locally? Make sure `polar webhook listen` is running and points at the right port and path.
- Log at each step of your handler (called, signature verified, handled) to see how far a request gets.

**`404`**

- Run `curl -v -X POST <endpoint-url>` to confirm the route exists.
- Check for a trailing slash. Many frameworks resolve `/foo` to `/foo/` with a redirect.

**`3xx`**

Redirects count as failures. Set the endpoint URL to the final destination. A common cause is a host that redirects between `www` and the bare domain, as Vercel can.

**`403`**

- Exclude the webhook route from authentication middleware. It must be publicly reachable.
- On Cloudflare, check the firewall logs and add a WAF rule that allows Polar's requests.
- Cloudflare's Bot Fight Mode blocks webhook requests, and allowlisting Polar's IPs or a WAF rule doesn't help. Turn it off under **Security → Bots** in Cloudflare.

### Invalid signature exceptions

- Pass the raw body, byte for byte. Parsing and re-serializing the JSON changes it.
- Check the secret. Each endpoint has its own, `polar webhook listen` prints a different one, and resetting a secret invalidates the old one immediately.
- Check your server's clock. The SDKs reject timestamps more than 5 minutes off.
- Rolling your own validation? See [Custom validation](#custom-validation) for which key to use.
