A **webhook endpoint** is a URL on your server that Polar sends events to, such as `order.paid` or `customer.state_changed`. Polar posts each event as soon as it happens, so you don't have to poll the API.

Every request is signed with the endpoint's secret. The TypeScript and Python SDKs verify the signature and return a typed payload. See [Handle deliveries](/integrate/webhooks/delivery).

<Info>
  Build against the [sandbox](/integrate/sandbox) first. Test purchases, renewals, cancellations and refunds there trigger the same events without real money.
</Info>

## Create an endpoint

The URL must use `https://` and be publicly reachable. Polar rejects `localhost` and private IP addresses. To receive events on your machine, use [`polar webhook listen`](#test-locally) instead.

<Tabs>
  <Tab title="Dashboard">
    - Open [**Settings → Webhooks**](https://polar.sh/to/dashboard/settings/webhooks)
    - Click **Add Endpoint**
    - Enter the **URL**, and an optional **Name**
    - Choose a **Format**: **Raw** for your own code, or **Discord** or **Slack**
    - Choose the **API Version** of the payloads
    - Select the **Events** you want to receive
    - Click **Create webhook**
  </Tab>
  <Tab title="CLI">
    ```bash
    polar webhooks create_webhook_endpoint \
      --url https://example.com/api/webhooks \
      --format raw \
      --api-version 2026-10 \
      --events customer.state_changed \
      --events order.paid
    ```

    Repeat `--events` for each event. The response includes the `secret`. See [`polar webhooks`](/integrate/cli/reference/webhooks#polar-webhooks-create_webhook_endpoint).
  </Tab>
  <Tab title="Prompt">
    ```text Prompt
    Create a webhook endpoint in my Polar sandbox organization for https://example.com/api/webhooks
    that receives customer.state_changed and order.paid, and show me its secret.
    ```

    Uses the `webhooks_create_webhook_endpoint` operation of the [Polar MCP server](/integrate/mcp).
  </Tab>
</Tabs>

To create endpoints from code, for example when you provision environments:

<CodeGroup>
```typescript TypeScript
const endpoint = await polar.webhooks.createWebhookEndpoint({
  url: "https://example.com/api/webhooks",
  format: "raw",
  events: ["customer.state_changed", "order.paid"],
});

console.log(endpoint.secret);
```

```python Python
endpoint = polar.webhooks.create_webhook_endpoint(
    url="https://example.com/api/webhooks",
    format="raw",
    events=["customer.state_changed", "order.paid"],
)

print(endpoint.secret)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/webhooks/endpoints \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/api/webhooks",
    "format": "raw",
    "events": ["customer.state_changed", "order.paid"]
  }'
```
</CodeGroup>

The examples use the sandbox client from [Authentication](/integrate/authentication#send-a-token), on API version `2026-10`. See [Create Webhook Endpoint](/api-reference/current/webhooks/create-webhook-endpoint).

### Format

- **Raw** sends the event as JSON. Use it for your own handlers.
- **Discord** and **Slack** turn the event into a chat message for a channel. Paste the channel's incoming webhook URL. When the URL starts with `https://discord.com/api/webhooks` or `https://hooks.slack.com/services/`, the dashboard selects the format for you.

### API version

Each endpoint has an API version, which sets the shape of its payloads. It defaults to the current version, `2026-10`. Use the same version as your SDK import (`@polar-sh/sdk/2026-10`, `polar.v2026_10`), so the SDK parses the payloads it receives. Every delivery carries the version in the `webhook-api-version` header.

### Events

Subscribe only to the events your handler acts on. For access control, `customer.state_changed` alone is often enough. See [Webhook events](/integrate/webhooks/events) for the full list.

## Copy the secret

Polar generates the secret when it creates the endpoint. You can't set your own.

- Open the endpoint in **Settings → Webhooks**
- Click **Copy Secret**
- Store it on your server as `POLAR_WEBHOOK_SECRET`

To rotate it, click **Reset Secret**, or run `polar webhooks reset_webhook_endpoint_secret <id>`. The old secret stops working immediately, so update your server right away.

Secrets generated on or after 8 September 2026, 00:00 UTC are signed with [Standard Webhooks](https://www.standardwebhooks.com/). Older secrets use Polar's original HMAC scheme. The endpoint page shows which one applies. See [Custom validation](/integrate/webhooks/delivery#custom-validation).

## Verify signature

Verify every request before you trust it. The SDKs do it in one call:

<CodeGroup>
```typescript TypeScript
import { webhooks } from "@polar-sh/sdk/2026-10";

const event = await webhooks.validateEvent(body, headers, process.env.POLAR_WEBHOOK_SECRET!);
```

```python Python
import os

from polar.v2026_10.webhooks import validate_event

event = validate_event(body, headers, os.environ["POLAR_WEBHOOK_SECRET"])
```
</CodeGroup>

`body` is the raw request body, before any JSON parsing. See [Handle deliveries](/integrate/webhooks/delivery#validate-and-parse-webhooks) for full handlers and error handling.

## Test locally

The [Polar CLI](/integrate/cli/webhooks) forwards your organization's webhooks to a URL on your machine, so you can test handlers before you deploy them:

```bash Terminal
curl -fsSL https://polar.sh/install.sh | bash
polar auth login --sandbox
polar webhook listen http://localhost:3000/api/webhooks
```

The CLI prints the secret it signs events with. Use it as `POLAR_WEBHOOK_SECRET` while you develop. To send a sample event on demand, run `polar webhook trigger order.created` in another terminal.

<Visibility for="agents">
  Test handlers with `polar webhook listen` rather than a tunnel. Always verify signatures with `validateEvent` / `validate_event` and the raw body. Never log or commit the webhook secret. Use the sandbox until the user says otherwise.
</Visibility>

## From the CLI or your agent

| Action | CLI | MCP operation |
| --- | --- | --- |
| List endpoints | `polar webhooks list_webhook_endpoints` | `webhooks_list_webhook_endpoints` |
| Update URL, events or format | `polar webhooks update_webhook_endpoint <id>` | `webhooks_update_webhook_endpoint` |
| Disable or enable | `polar webhooks update_webhook_endpoint <id> --enabled=false` | `webhooks_update_webhook_endpoint` |
| Reset the secret | `polar webhooks reset_webhook_endpoint_secret <id>` | `webhooks_reset_webhook_endpoint_secret` |
| Delete | `polar webhooks delete_webhook_endpoint <id>` | `webhooks_delete_webhook_endpoint` |

See the [CLI reference](/integrate/cli/reference/webhooks) and [MCP operations](/agents/mcp-operations).
