---
title: "3. Integrate checkout & customers"
description: "Link Polar customers to your users and send them to checkout."
---

<Info>
  **Why this matters:** Every order, subscription, benefit and usage event belongs to a customer. Linking customers to your own users by external ID means you never have to store Polar's IDs. See [Customers](/concepts/customers).
</Info>

In this step you'll create a customer for one of your users, then send them to a checkout for **Pro**.

## Create the customer when a user signs up

Create a Polar customer when a user signs up in your application, with your user ID as `external_id`:

<CodeGroup>
```typescript TypeScript
await polar.customers.create({
  email: "jane@example.com",
  external_id: "user_123",
});
```

```python Python
polar.customers.create(
    email="jane@example.com",
    external_id="user_123",
)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/customers/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "email": "jane@example.com", "external_id": "user_123" }'
```
</CodeGroup>

The events you sent in [step 1](/quickstart/track-usage) with `external_customer_id: "user_123"` now belong to this customer.

Creating customers up front is optional, since checkout creates the customer if it doesn't exist. Doing it at sign-up means usage, free plans and the [customer portal](/features/customer-portal/introduction) work from the first moment.

## Send the user to checkout

When the user clicks **Upgrade**, create a checkout session from your backend and redirect them to the `url` in the response:

<CodeGroup>
```typescript TypeScript
const checkout = await polar.checkouts.create({
  products: [product.id],
  external_customer_id: "user_123",
  success_url: "https://example.com/billing?checkout_id={CHECKOUT_ID}",
});

redirect(checkout.url);
```

```python Python
checkout = polar.checkouts.create(
    products=[product.id],
    external_customer_id="user_123",
    success_url="https://example.com/billing?checkout_id={CHECKOUT_ID}",
)

return redirect(checkout.url)
```

```bash cURL
curl -X POST https://sandbox-api.polar.sh/v1/checkouts/ \
  -H "Authorization: Bearer $POLAR_ACCESS_TOKEN" \
  -H "Polar-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{
    "products": ["'"$PRODUCT_ID"'"],
    "external_customer_id": "user_123",
    "success_url": "https://example.com/billing?checkout_id={CHECKOUT_ID}"
  }'
```
</CodeGroup>

Passing `external_customer_id` ties the purchase to your user and locks the email field to theirs. After paying, the customer returns to your `success_url`, with `{CHECKOUT_ID}` replaced by the session ID.

<Tip>
  Don't need per-user sessions? Create a [Checkout Link](/features/checkout/links) in the dashboard and link to it from your pricing page. To keep customers on your site, use [embedded checkout](/features/checkout/embed).
</Tip>
