The worker's scheduler ([`polar/worker/scheduler.py`](https://github.com/polarsource/polar/blob/main/server/polar/worker/scheduler.py))
runs an APScheduler instance next to Dramatiq. Any actor declared with a `cron_trigger` is
registered as a job and enqueued on its schedule:

```python
@actor(
    actor_name="external_event.prune",
    cron_trigger=CronTrigger.from_crontab("36 4 * * *"),
    priority=TaskPriority.LOW,
    max_retries=0,
)
async def external_event_prune() -> None: ...
```

**All schedules are UTC.** The scheduler has no notion of a local timezone, and neither should
you when reading this page.

This page is the registry of those jobs. It is the source of truth for "what runs when", so a
PR that adds, moves or removes a scheduled job updates the table in the same PR.

## The daily maintenance window: 04:00–05:00 UTC

Daily jobs run staggered inside a maintenance window between 04:00 and 05:00 UTC, one job per
slot, four minutes apart — see
[ADR-0013](/engineering/decisions/0013-daily-maintenance-window). 04:00–05:00 UTC is our
lowest-traffic hour, and spreading the jobs keeps a dozen bulk deletes from landing on the
database at the same instant.

**Adding a daily job:** take the next free slot below, declare it as
`CronTrigger.from_crontab("<minute> 4 * * *")`, and add its row here. Two daily jobs never
share a minute.

| 04:28 | `customer_email_update.delete_expired` | `customer_email_update` | Delete expired customer email change requests |
| 04:32 | `email_update.delete_expired_record` | `email_update` | Delete expired user email change requests |

`organization.cancel_expired_subscriptions` deliberately sits after
`organization.offboard_expired`: an org offboarded in this window should have its subscriptions
cancelled in the same pass.

Fifteen slots fit at four-minute spacing. When the window fills, tighten the spacing rather
than spilling past 05:00.

## Weekly jobs

| Schedule (UTC) | Actor | Module | What it does |
|---|---|---|---|
| Mon 09:00 | `slo_report.send_weekly` | `observability/slo_report` | Post the weekly SLO report to Slack |

This one is intentionally outside the window: it exists to be read by a human on Monday
morning, so the time of day is the point.

## Outside the scheduler

Not every recurring job is a Dramatiq actor. For completeness:

- **`polar-production-backup-copy`** — daily at 12:00 UTC, an EventBridge-scheduled ECS task
  (`terraform/production/backups.tf`). It copies snapshots rather than reading the primary, so
  it is not part of the maintenance window.

## Verifying the registry

To list what the code actually declares:

```bash
cd server && grep -rn "cron_trigger" polar --include=tasks.py
```

If that output and the tables above disagree, the code is right and this page is stale — fix it.
