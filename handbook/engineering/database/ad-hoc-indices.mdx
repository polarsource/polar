## Customer meter usage aggregation

The [PlanetScale query fingerprint](https://app.planetscale.com/polar-sh/polar-production/main/insights/9b386e778e98655e63f709a2a3f65bf558d96a0d0e10467740e6d5107ffcce13?keyspace=polar_production.public)
sums a numeric field from `events.user_metadata`. It combines two sums with `UNION ALL`:
one filters by `customer_id`, the other by `external_customer_id`. Both filter by
organization, event name, and source. The query has no time bound.

The indices below cover the `external_customer_id` branch. The partial predicate
limits each index to one organization and event name. Including `user_metadata`
lets PostgreSQL check the JSON value's type and compute the sum from the index when
an index-only scan is possible.

```sql
CREATE INDEX CONCURRENTLY IF NOT EXISTS "<index_name>"
ON events (external_customer_id, ingested_at)
INCLUDE (user_metadata)
WHERE organization_id = '<organization_id>'::uuid
  AND source = 'user'
  AND name = '<event_name>'
  AND external_customer_id IS NOT NULL;
```

Use the `ix_events_meter_` prefix for these manually managed indices. Alembic
autogeneration ignores database-only indices with this prefix on `events`.
