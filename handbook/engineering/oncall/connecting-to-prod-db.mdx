---
title: "Connecting to the Database"
description: "Query Render Postgres over Tailscale on the private network"
---

Query Render Postgres over Tailscale. Do not add a laptop IP under **Access Control** on the database. Engineer access stays on Tailscale. An allowlist entry publishes the database on the public internet.

Sandbox data is a database on the production `db` instance. Test is the separate `db-test` instance. Every instance on the account uses the same private-network suffix.

<Warning>
  These instances hold live data. Confirm the database name before running anything that writes. Use a read replica when you only need to inspect rows.
</Warning>

## Prerequisites

- Tailscale is connected to the company tailnet, with Tailscale DNS enabled. The hostname below resolves only through that DNS.
- Access to the database in the [Render Dashboard](https://dashboard.render.com/).

## 1. Copy the internal credentials

On the instance's **Connect** or **Info** page, copy the **internal** user, password, port, and database name.

The internal host is a bare id such as `dpg-xxxxxxxx-a`. Do not use the external hostname (`*.render.com`).

## 2. Build the Tailscale hostname

Append `.usr-cgvspcgdh87jokuesjfg.svc.cluster.local` to that id:

```text
dpg-xxxxxxxx-a.usr-cgvspcgdh87jokuesjfg.svc.cluster.local
```

Copy the `dpg-` id from the internal host on the Render page. `db-test` and each read replica have their own id. Use that id with the same suffix.

## 3. Connect

Use the internal port, `5432`. This path is the private network, so TLS is not required. Leave SSH tunneling off.

```bash
psql "host=dpg-xxxxxxxx-a.usr-cgvspcgdh87jokuesjfg.svc.cluster.local port=5432 user=USER dbname=DATABASE sslmode=disable"
```

`psql` prompts for the password. TablePlus and Postico take the same host, port, user, and database.

Sandbox is the `polar_sandbox` database on this same host. Production application data is the database name in the production service's internal URL.
