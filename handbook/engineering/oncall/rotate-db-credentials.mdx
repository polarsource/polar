---
title: "Rotate Database Credentials"
description: "Rotate PlanetScale Postgres credentials and update application secrets in Terraform Cloud."
---

<Warning>
  Coordinate with the on-call engineer and platform lead before rotating credentials.
  Resetting a role's password can interrupt new connections until every consumer has the new password.
</Warning>

## When to use this

- Suspected or confirmed credential leak
- Routine, scheduled rotation
- Offboarding / revoking database access

## Current configuration

All environments run on PlanetScale. Terraform manages the application role through `module.planetscale`.
Its password is supplied separately through the sensitive `planetscale_app_password` variable in the environment's Terraform Cloud variable set.

Both application and read connections use this password, including the `app` and `read` PgBouncers.
Changing the Terraform Cloud variable alone does not change the password in PlanetScale.

## Procedure

1. Confirm the target environment and role, and identify every consumer of its credentials before making changes. Include API services, workers, migration jobs, and any tools using the same role.
2. Reset the target role's password in PlanetScale. The module exposes `app_role_id` to identify the application role for `pscale role reset`; follow the [PlanetScale CLI role documentation](https://planetscale.com/docs/cli/role).
3. Store the new password securely. For the application role, update `planetscale_app_password` in the matching Terraform Cloud variable set (`production`, `sandbox`, or `test`). Update any matching credentials stored in 1Password and any consumers configured outside Terraform.
4. Review and apply the environment's plan in [Terraform Cloud](https://app.terraform.io/app/polar-sh/workspaces). Confirm that the plan updates the expected application secrets without replacing database resources or roles.
5. Redeploy affected API services and workers so they load the new credentials. Verify both application and read connections, and check for authentication errors.

Roles with separate credentials, such as `analytics_reader`, must be rotated independently and their consumers updated separately.

## Verification

- [ ] API services and workers can open new application and read connections
- [ ] Migration jobs and other affected consumers use the new credentials
- [ ] Credentials in 1Password match the intended role and environment
- [ ] Old credentials can no longer open new connections
- [ ] Operation recorded in the on-call log (see [Safety Guidelines](/engineering/oncall/introduction#safety-guidelines))

## Troubleshooting

If authentication fails after a reset, confirm that the Terraform Cloud variable matches the new PlanetScale password, apply the configuration, and redeploy affected consumers. Resetting a password does not update running services automatically.
