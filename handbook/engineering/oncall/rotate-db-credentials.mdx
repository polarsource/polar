---
title: "Rotate Database Credentials"
description: "Rotate PlanetScale Postgres credentials and update application secrets in Terraform Cloud."
---

<Warning>
  Coordinate with the on-call engineer and platform lead before rotating credentials.
  A misstep during the role swap can cut services off from the database.
</Warning>

## When to use this

- Suspected or confirmed credential leak
- Routine, scheduled rotation
- Offboarding / revoking database access

## Current configuration

All environments run on PlanetScale. Terraform manages the application role through `module.planetscale`.
Its password is supplied separately through the sensitive `planetscale_app_password` variable in the environment's Terraform Cloud variable set.

Both application and read connections use this password, including the `app` and `read` PgBouncers.
Changing the Terraform Cloud variable alone does not change the password in PlanetScale.

## Procedure

Rotate with a role swap to avoid downtime: add a new role, move every consumer to it, then remove the old role. Do not reset the existing role's password while consumers are still using it — new connections will fail until every consumer has the new credentials.

1. Add a new role for the target environment in PlanetScale, for example with `pscale role create`. Grant it the same access as the current application role; see the [PlanetScale CLI role documentation](https://planetscale.com/docs/cli/role).
2. Switch over all services and consumers to the new role. Update the `planetscale_app_password` variable in the matching Terraform Cloud variable set (`production`, `sandbox`, or `test`) to the new role's password, and update any connection configuration that references the role name — PgBouncer usernames, 1Password entries, and any tools configured outside Terraform.
3. Apply the environment's plan in [Terraform Cloud](https://app.terraform.io/app/polar-sh/workspaces) and redeploy every API service, worker, and migration job so they load the new credentials. Wait until all consumers are on the new role and the old role has zero active connections.
4. Remove the old role in PlanetScale, for example with `pscale role delete`, once nothing is connecting as it.

Roles with separate credentials, such as `analytics_reader`, must be rotated independently and their consumers updated separately.

## Verification

- [ ] API services and workers can open new application and read connections
- [ ] Migration jobs and other affected consumers use the new credentials
- [ ] Credentials in 1Password match the intended role and environment
- [ ] Old credentials can no longer open new connections
- [ ] Operation recorded in the on-call log (see [Safety Guidelines](/engineering/oncall/introduction#safety-guidelines))

## Troubleshooting

If authentication fails after the switch, confirm that the Terraform Cloud variable matches the new role's password and that the role exists in PlanetScale with the expected access, apply the configuration, and redeploy affected consumers.
